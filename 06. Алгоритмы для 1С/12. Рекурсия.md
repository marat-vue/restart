> [!abstract] Коротко
> **Рекурсия** — функция, которая вызывает саму себя для задачи **меньшего** размера. Обязательны две части: **базовый случай** (когда ответ известен сразу и вызовы прекращаются) и **рекурсивный шаг** (сводим задачу к меньшей). Без базового случая — бесконечная рекурсия и переполнение стека вызовов. Наивная рекурсия может многократно пересчитывать одно и то же (Фибоначчи — `O(2ⁿ)`); **мемоизация** — запоминание уже посчитанных ответов в соответствии — снижает это до `O(n)`. Рекурсия естественна для деревьев: иерархические справочники, вложенные группы.

## Что такое рекурсия

**Рекурсия** — когда функция для решения задачи вызывает **саму себя**, но с задачей поменьше.

Пример из жизни — **матрёшка**. Как узнать, сколько всего матрёшек вложено?

```text
Посчитать(матрёшка):
    если внутри пусто → это 1 матрёшка           ← базовый случай
    иначе → 1 + Посчитать(матрёшка внутри)       ← рекурсивный шаг
```

Мы не знаем сразу, сколько их всего, но знаем, как свести задачу к **меньшей**: «эта матрёшка плюс все, что внутри неё».

Любая рекурсия состоит из двух частей:

| Часть | Вопрос | Матрёшка |
| --- | --- | --- |
| **Базовый случай** | Когда ответ известен без дальнейших вызовов? | Внутри пусто — ответ 1 |
| **Рекурсивный шаг** | Как свести задачу к меньшей того же вида? | 1 + количество во внутренней |

## Пример 1. Факториал

`n! = 1 × 2 × 3 × … × n`. Например, `5! = 120`. Заметим: `5! = 5 × 4!`, а `4! = 4 × 3!`… — задача сводится к меньшей.

```1C
&НаКлиенте
Функция Факториал(n)
	Если n <= 1 Тогда
		Возврат 1;                   // базовый случай: 0! = 1! = 1
	КонецЕсли;
	Возврат n * Факториал(n - 1);    // рекурсивный шаг
КонецФункции
```

Как это выполняется для `Факториал(4)`:

```text
Факториал(4) = 4 × Факториал(3)
                   Факториал(3) = 3 × Факториал(2)
                                      Факториал(2) = 2 × Факториал(1)
                                                         Факториал(1) = 1   ← базовый случай
                                      Факториал(2) = 2 × 1 = 2
                   Факториал(3) = 3 × 2 = 6
Факториал(4) = 4 × 6 = 24
```

Вызовы «уходят вглубь», пока не дойдут до базового случая, а затем результаты «возвращаются наверх». Каждый незавершённый вызов ждёт в **стеке вызовов** ([[11. Стек и очередь]]) — его можно увидеть в отладчике Конфигуратора (окно «Стек вызовов»).

```1C
Проверить("5!", Факториал(5), 120);
Проверить("0!", Факториал(0), 1);
```

> [!warning] Без базового случая — переполнение
> Если забыть базовый случай (или написать его так, что он никогда не срабатывает), функция будет вызывать себя бесконечно. Каждый вызов занимает место в стеке вызовов, и платформа остановит выполнение с ошибкой переполнения стека. Первое, что проверяем в рекурсивной функции: **дойдёт ли она когда-нибудь до базового случая?**

Факториал легко написать и циклом — рекурсия здесь для обучения. Но есть задачи, где рекурсия гораздо естественнее цикла: деревья и перебор вариантов.

## Пример 2. Обход дерева: иерархический справочник

Справочник `Номенклатура` в учебной базе иерархический: группы содержат элементы и другие группы ([[01. Основы конфигурирования/08. Справочники|08. Справочники]]). Задача: посчитать **все** товары внутри группы на любой глубине вложенности.

```text
Бытовая техника
├─ Чайники
│  ├─ Чайник «Победа»
│  └─ Чайник «Ветерок»
├─ Блендер
└─ Кухонные весы
   └─ Весы «Точность»
```

Цикл здесь неудобен: мы не знаем, сколько уровней вложенности. А рекурсивно — естественно: «количество в группе = сумма по всем детям, где у группы-ребёнка считаем её количество тем же способом».

Для учебного примера представим дерево структурами: у узла есть `Имя` и массив `Дети`.

```1C
&НаКлиенте
Функция НовыйУзел(Имя)
	Возврат Новый Структура("Имя, Дети", Имя, Новый Массив);
КонецФункции

&НаКлиенте
Функция ПосчитатьЛистья(Узел)
	Если Узел.Дети.Количество() = 0 Тогда
		Возврат 1;                               // лист — это товар
	КонецЕсли;
	Всего = 0;
	Для Каждого Ребенок Из Узел.Дети Цикл
		Всего = Всего + ПосчитатьЛистья(Ребенок); // тот же вопрос — для ребёнка
	КонецЦикла;
	Возврат Всего;
КонецФункции
```

Собираем дерево и проверяем:

```1C
Техника = НовыйУзел("Бытовая техника");
Чайники = НовыйУзел("Чайники");
Чайники.Дети.Добавить(НовыйУзел("Чайник «Победа»"));
Чайники.Дети.Добавить(НовыйУзел("Чайник «Ветерок»"));
Весы = НовыйУзел("Кухонные весы");
Весы.Дети.Добавить(НовыйУзел("Весы «Точность»"));
Техника.Дети.Добавить(Чайники);
Техника.Дети.Добавить(НовыйУзел("Блендер"));
Техника.Дети.Добавить(Весы);

Проверить("Товаров в технике", ПосчитатьЛистья(Техника), 4);
```

Тот же подход — найти глубину дерева, вывести дерево с отступами, найти элемент по имени. В реальной базе с иерархией удобнее работать запросом с `В ИЕРАРХИИ` ([[03. Язык запросов и СКД/06. Ссылки, иерархия и составные типы|06. Иерархия в запросах]]), но на собеседовании ждут именно рекурсивного обхода.

## Пример 3. Фибоначчи и повторные вычисления

Числа Фибоначчи: каждое — сумма двух предыдущих. `0, 1, 1, 2, 3, 5, 8, 13, 21…`

```1C
&НаКлиенте
Функция ФибоначчиНаивно(n)
	Если n <= 1 Тогда
		Возврат n;
	КонецЕсли;
	Возврат ФибоначчиНаивно(n - 1) + ФибоначчиНаивно(n - 2);
КонецФункции
```

Код верный, но **очень медленный**. Посмотрим на дерево вызовов для `n = 5`:

```text
                    Ф(5)
               /           \
           Ф(4)             Ф(3)
          /    \           /    \
       Ф(3)    Ф(2)     Ф(2)    Ф(1)
      /   \    /  \     /  \
   Ф(2) Ф(1) Ф(1) Ф(0) Ф(1) Ф(0)
   /  \
Ф(1) Ф(0)
```

`Ф(3)` считается 2 раза, `Ф(2)` — 3 раза. С ростом `n` повторов становится всё больше: число вызовов растёт примерно как `2ⁿ`. Для `n = 40` — сотни миллионов вызовов, программа «зависнет».

### Мемоизация: запоминаем посчитанное

Решение — **запоминать** уже вычисленные значения и не пересчитывать их. Храним в соответствии «n → ответ» ([[05. Соответствие как хеш-таблица]]):

```1C
&НаКлиенте
Функция Фибоначчи(n, Память = Неопределено)
	Если Память = Неопределено Тогда
		Память = Новый Соответствие;   // создаём один раз при первом вызове
	КонецЕсли;
	Если n <= 1 Тогда
		Возврат n;
	КонецЕсли;
	Известно = Память.Получить(n);
	Если Известно <> Неопределено Тогда
		Возврат Известно;              // уже считали — берём из памяти
	КонецЕсли;
	Результат = Фибоначчи(n - 1, Память) + Фибоначчи(n - 2, Память);
	Память.Вставить(n, Результат);     // запоминаем
	Возврат Результат;
КонецФункции
```

Теперь каждое значение от 2 до `n` считается **один раз**: время `O(n)`, память `O(n)`. `Фибоначчи(80)` считается мгновенно. Соответствие передаётся во все вызовы по ссылке — все они пишут в одну общую «память».

```1C
Проверить("Ф(10)", Фибоначчи(10), 55);
Проверить("Ф(50)", Фибоначчи(50), 12586269025);
```

Мемоизация — первый шаг к **динамическому программированию** ([[14. Динамическое программирование]]).

## Пример 4. Перебор вариантов: все подмножества

Рекурсия удобна для перебора: на каждом шаге **принимаем решение** («брать элемент или нет») и рекурсивно решаем для оставшихся.

**Задача.** Вывести все подмножества набора `[1, 2, 3]`: `[]`, `[1]`, `[2]`, `[3]`, `[1,2]`, `[1,3]`, `[2,3]`, `[1,2,3]`.

```1C
&НаКлиенте
Процедура ВсеПодмножества(Числа, Индекс, Текущее, Результат)
	Если Индекс > Числа.ВГраница() Тогда
		Результат.Добавить(МассивВСтроку(Текущее));   // решения приняты для всех элементов
		Возврат;
	КонецЕсли;

	// Вариант 1: не берём Числа[Индекс]
	ВсеПодмножества(Числа, Индекс + 1, Текущее, Результат);

	// Вариант 2: берём Числа[Индекс]
	Текущее.Добавить(Числа[Индекс]);
	ВсеПодмножества(Числа, Индекс + 1, Текущее, Результат);
	Текущее.Удалить(Текущее.ВГраница());              // «откатываем» решение
КонецПроцедуры
```

Вызов:

```1C
Результат = Новый Массив;
ВсеПодмножества(ЧислаИзСтроки("1,2,3"), 0, Новый Массив, Результат);
Проверить("Подмножеств", Результат.Количество(), 8);
```

Этот приём — **перебор с возвратом** (backtracking): попробовали вариант, ушли вглубь, вернулись и **отменили** изменение (`Текущее.Удалить(…)`), чтобы попробовать следующий. Подмножеств `2ⁿ` — для перебора это нормальная, неизбежная сложность.

## Рекурсия или цикл

| | Рекурсия | Цикл |
| --- | --- | --- |
| Деревья, вложенность неизвестной глубины | Естественно | Нужен свой стек |
| Перебор вариантов | Естественно | Сложно |
| Простой проход по массиву | Избыточно | Естественно |
| Очень большая глубина (десятки тысяч уровней) | Риск переполнения стека | Безопасно |

> [!question]- Проверь себя
> 1. Из каких двух частей состоит любая рекурсивная функция?
> 2. Что произойдёт, если базовый случай никогда не сработает?
> 3. Почему наивный рекурсивный Фибоначчи медленный и как его ускорить?
> 4. Зачем в переборе подмножеств строка `Текущее.Удалить(Текущее.ВГраница())`?
>
> > [!success]- Ответы
> > 1. Базовый случай и рекурсивный шаг, сводящий задачу к меньшей.
> > 2. Бесконечная рекурсия: стек вызовов переполнится, выполнение прервётся с ошибкой.
> > 3. Одни и те же значения пересчитываются много раз — `O(2ⁿ)`. Мемоизация: запоминать посчитанные значения в соответствии — `O(n)`.
> > 4. Чтобы отменить решение «взять элемент» после возврата из вызова и корректно перебрать следующие варианты (перебор с возвратом).
