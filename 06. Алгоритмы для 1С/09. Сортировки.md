> [!abstract] Коротко
> Простые сортировки — **пузырьком**, **выбором**, **вставками** — работают за `O(n²)`: понятны, но медленны на больших данных. **Сортировка слиянием** — `O(n log n)`: делим массив пополам, сортируем половины рекурсивно и сливаем. **Подсчётом** — `O(n + k)` для небольших целых чисел. В рабочем коде 1С массив сортируют встроенными средствами: `СписокЗначений.СортироватьПоЗначению()` или `ТаблицаЗначений.Сортировать()`; у самого массива метода сортировки нет. На собеседовании просят объяснить идею и сложность, иногда — написать простую сортировку или слияние.

## Зачем знать сортировки, если есть встроенные

Сортировку на собеседовании просят по трём причинам:
1. Проверить, умеете ли вы писать циклы с индексами без ошибок.
2. Проверить понимание сложности: почему одни сортировки медленные, а другие быстрые.
3. Сортировка — шаг в решении многих задач: «отсортировать, а потом два указателя» или «отсортировать интервалы и слить» ([[15. Жадные алгоритмы и интервалы]]).

## Встроенная сортировка в 1С

Сначала — как сортировать в **рабочем** коде. У типа `Массив` метода сортировки нет. Используем `СписокЗначений`:

```1C
&НаКлиенте
Функция ОтсортироватьМассив(Числа, ПоУбыванию = Ложь)
	Список = Новый СписокЗначений;
	Список.ЗагрузитьЗначения(Числа);
	Список.СортироватьПоЗначению(?(ПоУбыванию, НаправлениеСортировки.Убыв, НаправлениеСортировки.Возр));
	Возврат Список.ВыгрузитьЗначения();
КонецФункции
```

На сервере, где доступна `ТаблицаЗначений`, сортируют по колонкам: `Таблица.Сортировать("Сумма Убыв, Наименование")` ([[02. Программирование/21. Таблицы значений|21. Таблицы значений]]). А данные из базы сортируют прямо в запросе — `УПОРЯДОЧИТЬ ПО`.

Встроенные сортировки работают за `O(n log n)`. Дальше — как такие алгоритмы устроены внутри.

## Сортировка пузырьком — O(n²)

**Идея.** Проходим по массиву и сравниваем соседей: если левый больше правого — меняем их местами. После первого прохода самый большой элемент «всплывает» в конец, как пузырёк воздуха. Повторяем проходы, каждый раз на один элемент короче.

```text
Проход 1: [5, 3, 8, 1]
           5>3 обмен → [3, 5, 8, 1]
              5<8      → [3, 5, 8, 1]
                 8>1 обмен → [3, 5, 1, 8]   ← 8 на месте
Проход 2: [3, 5, 1 | 8]
           3<5         → [3, 5, 1]
              5>1 обмен → [3, 1, 5]         ← 5 на месте
Проход 3: [3, 1 | 5, 8]
           3>1 обмен → [1, 3]               ← готово: [1, 3, 5, 8]
```

```1C
&НаКлиенте
Процедура СортировкаПузырьком(Числа)
	n = Числа.Количество();
	Для Проход = 1 По n - 1 Цикл
		БылиОбмены = Ложь;
		Для i = 0 По n - 1 - Проход Цикл
			Если Числа[i] > Числа[i + 1] Тогда
				Временная = Числа[i];
				Числа[i] = Числа[i + 1];
				Числа[i + 1] = Временная;
				БылиОбмены = Истина;
			КонецЕсли;
		КонецЦикла;
		Если НЕ БылиОбмены Тогда
			Прервать;   // обменов не было — массив уже отсортирован
		КонецЕсли;
	КонецЦикла;
КонецПроцедуры
```

Два вложенных цикла — `O(n²)`. Флаг `БылиОбмены` ускоряет работу на почти отсортированных данных: на уже отсортированном массиве хватит одного прохода — `O(n)`.

## Сортировка вставками — O(n²)

**Идея.** Так сортируют карты в руке: берём очередную карту и вставляем её на нужное место среди уже упорядоченных слева.

```text
[5 | 3, 8, 1]     левая часть [5] отсортирована
[3, 5 | 8, 1]     3 вставили перед 5
[3, 5, 8 | 1]     8 уже на месте
[1, 3, 5, 8]      1 сдвинулась в самое начало
```

```1C
&НаКлиенте
Процедура СортировкаВставками(Числа)
	Для i = 1 По Числа.ВГраница() Цикл
		Текущий = Числа[i];
		j = i - 1;
		// Сдвигаем вправо все элементы, которые больше текущего
		Пока j >= 0 И Числа[j] > Текущий Цикл
			Числа[j + 1] = Числа[j];
			j = j - 1;
		КонецЦикла;
		Числа[j + 1] = Текущий;   // вставляем на освободившееся место
	КонецЦикла;
КонецПроцедуры
```

Условие `j >= 0 И Числа[j] > Текущий` безопасно благодаря **сокращённому вычислению**: если `j = −1`, вторая часть не проверяется, и выхода за границу нет ([[02. Программирование/07. Работа с булевым типом|07. Булево]]).

В худшем случае `O(n²)`, на почти отсортированных данных — близко к `O(n)`.

## Сортировка слиянием — O(n log n)

**Идея «разделяй и властвуй»:**
1. Если в массиве 0 или 1 элемент — он уже отсортирован.
2. Иначе делим массив пополам.
3. Сортируем каждую половину **тем же способом** (рекурсивно — функция вызывает саму себя, подробнее в [[12. Рекурсия]]).
4. Сливаем две отсортированные половины в одну — это мы умеем делать за линейное время ([[06. Два указателя]]).

```text
                [5, 3, 8, 1, 9, 2]
               /                  \
        [5, 3, 8]                [1, 9, 2]
        /       \                /       \
     [5]     [3, 8]           [1]      [9, 2]
             /    \                    /    \
           [3]    [8]                [9]    [2]
             \    /                    \    /
     [5]     [3, 8]           [1]      [2, 9]
        \       /                \       /
        [3, 5, 8]                [1, 2, 9]
               \                  /
                [1, 2, 3, 5, 8, 9]
```

```1C
&НаКлиенте
Функция СортировкаСлиянием(Числа)
	Если Числа.Количество() <= 1 Тогда
		Возврат Числа;   // базовый случай: уже отсортирован
	КонецЕсли;

	Середина = Цел(Числа.Количество() / 2);
	Левая = Новый Массив;
	Правая = Новый Массив;
	Для i = 0 По Числа.ВГраница() Цикл
		Если i < Середина Тогда
			Левая.Добавить(Числа[i]);
		Иначе
			Правая.Добавить(Числа[i]);
		КонецЕсли;
	КонецЦикла;

	Возврат СлитьОтсортированные(СортировкаСлиянием(Левая), СортировкаСлиянием(Правая));
КонецФункции
```

Функция `СлитьОтсортированные` — из урока [[06. Два указателя]].

**Почему `O(n log n)`.** Массив делится пополам, пока куски не станут по одному элементу, — это `log n` уровней (как в бинарном поиске). На каждом уровне слияние суммарно обрабатывает все `n` элементов. Итого `n × log n`. Дополнительная память — `O(n)` на временные массивы.

```1C
Проверить("Слиянием", МассивВСтроку(СортировкаСлиянием(ЧислаИзСтроки("5,3,8,1,9,2"))), "1,2,3,5,8,9");
Проверить("Пустой", МассивВСтроку(СортировкаСлиянием(ЧислаИзСтроки(""))), "");
```

> [!info] Быстрая сортировка
> На собеседовании могут спросить и про **быструю сортировку (quicksort)**: выбираем опорный элемент, раскладываем остальные на «меньше» и «больше» и сортируем части рекурсивно. В среднем `O(n log n)`, в худшем случае (неудачные опорные элементы) — `O(n²)`. Достаточно знать идею и сложность.

## Сортировка подсчётом — O(n + k)

Если значения — небольшие **целые** числа (например, оценки от 1 до 5 или возраст от 0 до 120), можно сортировать вообще без сравнений: посчитать, сколько раз встречается каждое значение, и выписать их по порядку.

```text
Оценки: [5, 3, 5, 1, 3, 5]
Счётчики: 1→1, 2→0, 3→2, 4→0, 5→3
Результат: 1, 3, 3, 5, 5, 5
```

```1C
&НаКлиенте
Функция СортировкаПодсчетом(Числа, Минимум, Максимум)
	Счетчики = Новый Массив(Максимум - Минимум + 1);
	Для i = 0 По Счетчики.ВГраница() Цикл
		Счетчики[i] = 0;
	КонецЦикла;
	Для Каждого Элемент Из Числа Цикл
		Счетчики[Элемент - Минимум] = Счетчики[Элемент - Минимум] + 1;
	КонецЦикла;
	Результат = Новый Массив;
	Для i = 0 По Счетчики.ВГраница() Цикл
		Для Повтор = 1 По Счетчики[i] Цикл
			Результат.Добавить(i + Минимум);
		КонецЦикла;
	КонецЦикла;
	Возврат Результат;
КонецФункции
```

Время `O(n + k)`, где `k` — размер диапазона значений. Подходит только когда диапазон небольшой: для чисел до миллиарда массив счётчиков будет огромным.

## Сравнение

| Алгоритм | Время (среднее) | Время (худшее) | Доп. память | Когда |
| --- | --- | --- | --- | --- |
| Пузырьком | `O(n²)` | `O(n²)` | `O(1)` | Учебный пример |
| Вставками | `O(n²)` | `O(n²)` | `O(1)` | Маленькие или почти отсортированные массивы |
| Слиянием | `O(n log n)` | `O(n log n)` | `O(n)` | Гарантированная скорость |
| Быстрая | `O(n log n)` | `O(n²)` | `O(log n)` | Часто самая быстрая на практике |
| Подсчётом | `O(n + k)` | `O(n + k)` | `O(k)` | Небольшие целые числа |
| Встроенная (`СортироватьПоЗначению`) | `O(n log n)` | — | — | Рабочий код |

> [!tip] Сортировка как первый шаг
> Многие задачи становятся простыми после сортировки: найти дубликаты (они окажутся рядом), пару с суммой (два указателя), слить пересекающиеся интервалы. Если решение «в лоб» `O(n²)`, спросите себя: «А если сначала отсортировать за `O(n log n)`?».

> [!question]- Проверь себя
> 1. Почему у массива в 1С нельзя вызвать сортировку и как отсортировать его в рабочем коде?
> 2. Объясните идею сортировки вставками на примере карт.
> 3. Почему сортировка слиянием работает за `O(n log n)`?
> 4. Когда выгодна сортировка подсчётом и когда она не подходит?
>
> > [!success]- Ответы
> > 1. У типа `Массив` нет такого метода. Загрузить значения в `СписокЗначений`, вызвать `СортироватьПоЗначению()`, выгрузить обратно; на сервере — `ТаблицаЗначений.Сортировать()`; данные из базы — `УПОРЯДОЧИТЬ ПО`.
> > 2. Берём очередную карту и сдвигаем её влево, пока слева не окажется карта меньше; левая часть всегда отсортирована.
> > 3. `log n` уровней деления пополам, на каждом уровне слияние обрабатывает все `n` элементов.
> > 4. Когда значения — целые числа из небольшого диапазона; не подходит для больших диапазонов, дробных чисел и строк.
