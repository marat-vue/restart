> [!abstract] Коротко
> **Бинарный поиск** находит элемент в **отсортированном** массиве за `O(log n)`: смотрим на середину, отбрасываем половину, где ответа точно нет, и повторяем. Миллион элементов — около 20 шагов. Главные трудности — границы: `Пока Левый <= Правый`, середина `Цел((Левый + Правый) / 2)`, сдвиг `Середина + 1` / `Середина − 1`. Вариант «найти первое место, где условие стало истинным» (нижняя граница) решает задачи «первый элемент ≥ X» и «первая плохая версия».

## Идея: игра «угадай число»

Я загадал число от 1 до 100. Вы называете число, я отвечаю «больше» или «меньше». Как угадать быстрее всего?

Плохая стратегия — перебор: 1, 2, 3… — до 100 попыток.

Хорошая — **каждый раз называть середину**:

```text
Загадано 73.
50?  → больше   (осталось 51–100)
75?  → меньше   (осталось 51–74)
62?  → больше   (осталось 63–74)
68?  → больше   (осталось 69–74)
71?  → больше   (осталось 72–74)
73?  → угадал! — 6 попыток
```

Каждый ответ отбрасывает **половину** вариантов. 100 → 50 → 25 → 13 → 7 → 4 → 2 → 1: не больше 7 попыток. Для миллиона вариантов — не больше 20, для миллиарда — 30. Это и есть `O(log n)`.

Обязательное условие: данные **отсортированы**. Ответ «больше» имеет смысл только потому, что числа идут по порядку.

## Классический бинарный поиск

**Задача.** Найти индекс числа `X` в отсортированном массиве; если его нет — вернуть `-1`.

```1C
&НаКлиенте
Функция БинарныйПоиск(Числа, X)
	Левый = 0;
	Правый = Числа.ВГраница();
	Пока Левый <= Правый Цикл
		Середина = Цел((Левый + Правый) / 2);
		Если Числа[Середина] = X Тогда
			Возврат Середина;                // нашли
		ИначеЕсли Числа[Середина] < X Тогда
			Левый = Середина + 1;            // X правее середины
		Иначе
			Правый = Середина - 1;           // X левее середины
		КонецЕсли;
	КонецЦикла;
	Возврат -1;                              // область поиска пуста — X нет
КонецФункции
```

Прогон: `[1, 3, 5, 7, 9, 11, 13]`, ищем `9`:

```text
Индексы:  0   1   2   3   4   5   6
Числа:   [1] [3] [5] [7] [9] [11][13]

Шаг 1: Л=0, П=6, С=3 → Числа[3]=7 < 9 → Л = 4
                       [9] [11][13]
Шаг 2: Л=4, П=6, С=5 → Числа[5]=11 > 9 → П = 4
                       [9]
Шаг 3: Л=4, П=4, С=4 → Числа[4]=9 = 9 → ответ 4
```

| Деталь | Почему именно так |
| --- | --- |
| `Пока Левый <= Правый` | При `Левый = Правый` в области остался **один** элемент — его тоже надо проверить. `<` пропустил бы его |
| `Цел((Левый + Правый) / 2)` | В 1С деление даёт дробь: `(4 + 5) / 2 = 4.5`. `Цел` отбрасывает дробную часть → индекс 4 |
| `Середина + 1`, `Середина − 1` | Середину уже проверили — исключаем её. Без `±1` возможен бесконечный цикл |

```1C
Числа = ЧислаИзСтроки("1,3,5,7,9,11,13");
Проверить("Найти 9", БинарныйПоиск(Числа, 9), 4);
Проверить("Первый", БинарныйПоиск(Числа, 1), 0);
Проверить("Последний", БинарныйПоиск(Числа, 13), 6);
Проверить("Нет такого", БинарныйПоиск(Числа, 8), -1);
Проверить("Пустой массив", БинарныйПоиск(ЧислаИзСтроки(""), 5), -1);
```

> [!warning] Самые частые ошибки
> - `Пока Левый < Правый` вместо `<=` — не находит элемент, когда остался один кандидат.
> - `Левый = Середина` вместо `Середина + 1` — бесконечный цикл, когда `Левый` и `Правый` соседние.
> - Поиск в **неотсортированном** массиве — ответ непредсказуем.

## Нижняя граница: первый элемент, не меньший X

Часто нужно не «найти точно», а «найти **первое** место, где выполняется условие». Например, первый элемент `≥ X`, или позицию, куда вставить `X`, чтобы массив остался отсортированным.

`[1, 3, 5, 5, 5, 8]`, `X = 5` → индекс `2` (первая пятёрка). `X = 6` → индекс `5` (первый элемент ≥ 6 — это 8). `X = 10` → индекс `6` (за концом массива — все элементы меньше).

```1C
&НаКлиенте
Функция НижняяГраница(Числа, X)
	Левый = 0;
	Правый = Числа.Количество();   // ответ может быть «за концом» — поэтому Количество, а не ВГраница
	Пока Левый < Правый Цикл
		Середина = Цел((Левый + Правый) / 2);
		Если Числа[Середина] < X Тогда
			Левый = Середина + 1;        // середина слишком мала — ответ правее
		Иначе
			Правый = Середина;           // середина подходит — ответ здесь или левее
		КонецЕсли;
	КонецЦикла;
	Возврат Левый;
КонецФункции
```

Обратите внимание на отличия от классического варианта: `Пока Левый < Правый`, а при подходящей середине — `Правый = Середина` (без −1), потому что середина сама может быть ответом. Область поиска — полуинтервал `[Левый, Правый)`, и цикл заканчивается, когда в нём ноль кандидатов, а `Левый` указывает на ответ.

```1C
Числа = ЧислаИзСтроки("1,3,5,5,5,8");
Проверить("Первая пятёрка", НижняяГраница(Числа, 5), 2);
Проверить("Первый ≥ 6", НижняяГраница(Числа, 6), 5);
Проверить("Все меньше", НижняяГраница(Числа, 10), 6);
```

С помощью нижней границы легко посчитать, **сколько раз** встречается `X` в отсортированном массиве: `НижняяГраница(Числа, X + 1) − НижняяГраница(Числа, X)` (для целых чисел) — за `O(log n)`.

## Бинарный поиск по ответу

Иногда отсортированного массива нет, но есть **монотонное условие**: до какого-то места оно ложно, а дальше всегда истинно.

**Задача «первая плохая версия».** Есть версии программы 1, 2, …, n. Начиная с какой-то версии, все версии содержат ошибку. Функция `ВерсияПлохая(Номер)` отвечает «да/нет». Найти первую плохую версию, вызвав функцию как можно меньше раз.

```text
Версии:  1  2  3  4  5  6  7  8
Плохая:  н  н  н  д  д  д  д  д     ← ответ 4
```

Это та же нижняя граница, только вместо `Числа[Середина] < X` — проверка условия:

```1C
&НаКлиенте
Функция ПерваяПлохаяВерсия(n)
	Левый = 1;
	Правый = n;
	Пока Левый < Правый Цикл
		Середина = Цел((Левый + Правый) / 2);
		Если ВерсияПлохая(Середина) Тогда
			Правый = Середина;           // плохая — ответ здесь или левее
		Иначе
			Левый = Середина + 1;        // хорошая — ответ правее
		КонецЕсли;
	КонецЦикла;
	Возврат Левый;
КонецФункции

// Для проверки: допустим, плохие — начиная с 4
&НаКлиенте
Функция ВерсияПлохая(Номер)
	Возврат Номер >= 4;
КонецФункции
```

`O(log n)` вызовов вместо `n`. Тот же приём решает задачи вида «найти минимальную скорость / вместимость / время, при которой условие выполняется» — если с ростом значения условие только «включается» и больше не «выключается».

## Когда думать о бинарном поиске

| Признак | Пример |
| --- | --- |
| Данные отсортированы, нужно найти элемент или позицию | Поиск в отсортированном списке кодов |
| «Первый / последний элемент, который…» | Первая дата, когда остаток стал отрицательным |
| Ответ — число в диапазоне, и проверка «подходит ли X» монотонна | Минимальная вместимость машины, чтобы развезти заказы за N дней |
| Требуют быстрее, чем `O(n)`, на отсортированных данных | — |

> [!question]- Проверь себя
> 1. Какое условие обязательно для бинарного поиска?
> 2. Почему в классическом варианте цикл `Пока Левый <= Правый`, а не `<`?
> 3. Зачем в 1С нужен `Цел` при вычислении середины?
> 4. Сколько шагов понадобится бинарному поиску в массиве из 1 000 000 элементов?
> 5. Чем нижняя граница отличается от классического поиска?
>
> > [!success]- Ответы
> > 1. Данные отсортированы (или условие монотонно: сначала ложно, потом всегда истинно).
> > 2. При `Левый = Правый` остаётся один непроверенный элемент; со `<` он бы пропустился.
> > 3. Деление в 1С даёт дробное число, а индекс должен быть целым.
> > 4. Около 20 (`log₂ 1 000 000 ≈ 20`).
> > 5. Ищет первое подходящее место, а не точное совпадение: при подходящей середине `Правый = Середина` (середина может быть ответом), цикл `Пока Левый < Правый`, начальное `Правый = Количество()`.
