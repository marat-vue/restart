> [!abstract] Коротко
> **Динамическое программирование (ДП)** — решение задачи через ответы на её **подзадачи**, где каждая подзадача решается **один раз** и запоминается. Рецепт: 1) что хранит `ДП[i]` (смысл состояния); 2) **переход** — как `ДП[i]` выражается через предыдущие; 3) **база** — начальные значения; 4) где ответ. Классика: лестница (`ДП[i] = ДП[i−1] + ДП[i−2]`), максимальная сумма подмассива (алгоритм Кадане), лучшая покупка-продажа акции, грабитель домов, путь в сетке. Обычно `O(n)` вместо экспоненциального перебора.

## Идея

В уроке о рекурсии мы ускорили Фибоначчи, **запоминая** уже посчитанные значения ([[12. Рекурсия]]). Это и есть суть динамического программирования:

1. Разбить задачу на **подзадачи** того же вида, но меньше.
2. Каждую подзадачу решить **один раз** и записать ответ в таблицу.
3. Большую задачу собрать из готовых ответов.

Аналогия: вас спрашивают «сколько будет 1+1+1+1+1+1+1+1?». Вы считаете — 8. Затем дописывают ещё «+1» и спрашивают снова. Вы не пересчитываете всё — сразу говорите 9, потому что **помните** предыдущий ответ.

Есть два способа записи:

| Способ | Как | Пример |
| --- | --- | --- |
| **Сверху вниз** (мемоизация) | Рекурсия + запоминание в соответствии | `Фибоначчи` из урока 12 |
| **Снизу вверх** (таблица) | Цикл заполняет массив `ДП` от маленьких подзадач к большим | Все примеры ниже |

Снизу вверх обычно проще и не грозит переполнением стека вызовов.

## Рецепт решения задачи на ДП

Каждый раз отвечайте на четыре вопроса — это и есть решение:

| Вопрос | Что определяем |
| --- | --- |
| 1. **Состояние** | Что означает `ДП[i]` словами? Это самый важный шаг |
| 2. **Переход** | Как вычислить `ДП[i]` через уже известные `ДП[i−1]`, `ДП[i−2]`…? |
| 3. **База** | Какие значения известны сразу (`ДП[0]`, `ДП[1]`)? |
| 4. **Ответ** | Где в таблице лежит ответ на исходную задачу? |

## Задача 1. Лестница

**Условие.** Лестница из `n` ступенек. За один шаг можно подняться на 1 или 2 ступеньки. Сколькими способами можно добраться до верха?

`n = 3` → 3 способа: `1+1+1`, `1+2`, `2+1`.

**Рассуждение.** На ступеньку `i` можно попасть только двумя способами: шагом с `i−1` или прыжком с `i−2`. Значит, число способов дойти до `i` = способы дойти до `i−1` + способы дойти до `i−2`.

| Вопрос | Ответ |
| --- | --- |
| Состояние | `ДП[i]` — число способов добраться до ступеньки `i` |
| Переход | `ДП[i] = ДП[i−1] + ДП[i−2]` |
| База | `ДП[0] = 1` (стоим внизу — один способ «ничего не делать»), `ДП[1] = 1` |
| Ответ | `ДП[n]` |

```text
i:     0   1   2   3   4   5
ДП:    1   1   2   3   5   8
               ↑
           ДП[2] = ДП[1] + ДП[0] = 1 + 1 = 2
```

Узнаёте? Это числа Фибоначчи.

```1C
&НаКлиенте
Функция СпособовПодняться(n)
	ДП = Новый Массив(n + 1);
	ДП[0] = 1;
	Если n >= 1 Тогда
		ДП[1] = 1;
	КонецЕсли;
	Для i = 2 По n Цикл
		ДП[i] = ДП[i - 1] + ДП[i - 2];
	КонецЦикла;
	Возврат ДП[n];
КонецФункции
```

Время `O(n)`, память `O(n)`. Каждое значение зависит только от двух предыдущих, поэтому можно хранить две переменные вместо массива — память `O(1)`. На собеседовании это хороший «следующий шаг» оптимизации.

```1C
Проверить("Лестница 3", СпособовПодняться(3), 3);
Проверить("Лестница 5", СпособовПодняться(5), 8);
Проверить("Лестница 1", СпособовПодняться(1), 1);
```

## Задача 2. Максимальная сумма подмассива (алгоритм Кадане)

Одна из самых частых задач собеседований.

**Условие.** Найти непрерывный подмассив с **максимальной** суммой и вернуть эту сумму. `[-2, 1, -3, 4, -1, 2, 1, -5, 4]` → `6` (подмассив `[4, -1, 2, 1]`).

Перебор всех подмассивов — `O(n²)`.

**Рассуждение.** Пусть `Лучший[i]` — максимальная сумма подмассива, который **заканчивается** на элементе `i`. Для элемента `i` выбор только один: продолжить лучший подмассив, закончившийся на `i−1`, или начать новый прямо с `i`.

```text
Лучший[i] = Макс(Числа[i], Лучший[i−1] + Числа[i])
```

Если «хвост» до `i−1` даёт отрицательную сумму, он только мешает — выгоднее начать заново.

| i | Числа[i] | Продолжить | Начать заново | Лучший[i] | Общий максимум |
| --- | --- | --- | --- | --- | --- |
| 0 | −2 | — | −2 | −2 | −2 |
| 1 | 1 | −2+1 = −1 | 1 | 1 | 1 |
| 2 | −3 | 1−3 = −2 | −3 | −2 | 1 |
| 3 | 4 | −2+4 = 2 | 4 | 4 | 4 |
| 4 | −1 | 4−1 = 3 | −1 | 3 | 4 |
| 5 | 2 | 3+2 = 5 | 2 | 5 | 5 |
| 6 | 1 | 5+1 = 6 | 1 | 6 | **6** |
| 7 | −5 | 6−5 = 1 | −5 | 1 | 6 |
| 8 | 4 | 1+4 = 5 | 4 | 5 | 6 |

Ответ — максимум по всем `Лучший[i]`: **6**.

```1C
&НаКлиенте
Функция МаксСуммаПодмассива(Числа)
	ЛучшийЗдесь = Числа[0];   // лучшая сумма подмассива, заканчивающегося на текущем элементе
	Ответ = Числа[0];
	Для i = 1 По Числа.ВГраница() Цикл
		ЛучшийЗдесь = Макс(Числа[i], ЛучшийЗдесь + Числа[i]);
		Ответ = Макс(Ответ, ЛучшийЗдесь);
	КонецЦикла;
	Возврат Ответ;
КонецФункции
```

Время `O(n)`, память `O(1)` — нам нужно только предыдущее значение, массив не храним.

```1C
Проверить("Кадане", МаксСуммаПодмассива(ЧислаИзСтроки("-2,1,-3,4,-1,2,1,-5,4")), 6);
Проверить("Все отрицательные", МаксСуммаПодмассива(ЧислаИзСтроки("-3,-1,-2")), -1);
```

> [!warning] Все числа отрицательные
> Если начать с `Ответ = 0`, для `[-3, -1, -2]` получим 0 — а такого подмассива нет (подмассив не может быть пустым). Поэтому стартуем с первого элемента.

## Задача 3. Лучшее время купить и продать

**Условие.** Даны цены акции по дням. Можно один раз купить и позже один раз продать. Найти максимальную прибыль (0, если прибыли не будет). `[7, 1, 5, 3, 6, 4]` → `5` (купить по 1, продать по 6).

**Рассуждение.** Продавая в день `i`, лучше всего было купить по **минимальной цене до этого дня**. Значит, идём по дням и помним минимум «на сегодня»:

```1C
&НаКлиенте
Функция МаксПрибыль(Цены)
	МинЦена = Цены[0];
	Прибыль = 0;
	Для i = 1 По Цены.ВГраница() Цикл
		Прибыль = Макс(Прибыль, Цены[i] - МинЦена);   // продать сегодня
		МинЦена = Мин(МинЦена, Цены[i]);              // или запомнить новую дешёвую цену
	КонецЦикла;
	Возврат Прибыль;
КонецФункции
```

| День | Цена | Мин. до дня | Прибыль, если продать сегодня | Лучшая прибыль |
| --- | --- | --- | --- | --- |
| 0 | 7 | 7 | — | 0 |
| 1 | 1 | 7 | −6 | 0 |
| 2 | 5 | 1 | 4 | 4 |
| 3 | 3 | 1 | 2 | 4 |
| 4 | 6 | 1 | **5** | 5 |
| 5 | 4 | 1 | 3 | 5 |

Время `O(n)`, память `O(1)`.

```1C
Проверить("Прибыль", МаксПрибыль(ЧислаИзСтроки("7,1,5,3,6,4")), 5);
Проверить("Только падение", МаксПрибыль(ЧислаИзСтроки("7,6,4,3,1")), 0);
```

## Задача 4. Грабитель домов

**Условие.** Дома стоят в ряд, в каждом лежит сумма денег. Нельзя брать деньги из **двух соседних** домов. Какую максимальную сумму можно собрать? `[2, 7, 9, 3, 1]` → `12` (дома 2 + 9 + 1).

| Вопрос | Ответ |
| --- | --- |
| Состояние | `ДП[i]` — максимум, который можно собрать с домов `0..i` |
| Переход | Для дома `i` два варианта: **не брать** его — `ДП[i−1]`; **взять** — `ДП[i−2] + Дома[i]` (соседний `i−1` тогда брать нельзя). `ДП[i] = Макс(ДП[i−1], ДП[i−2] + Дома[i])` |
| База | `ДП[0] = Дома[0]`, `ДП[1] = Макс(Дома[0], Дома[1])` |
| Ответ | `ДП[n−1]` |

```text
Дома: 2   7   9   3   1
ДП:   2   7  11  11  12
              ↑
        ДП[2] = Макс(ДП[1]=7, ДП[0]+9=11) = 11
```

```1C
&НаКлиенте
Функция ОграбитьДома(Дома)
	Если Дома.Количество() = 0 Тогда
		Возврат 0;
	КонецЕсли;
	ДоПредыдущего = 0;        // ДП[i − 2]
	Предыдущий = 0;           // ДП[i − 1]
	Для Каждого Деньги Из Дома Цикл
		Текущий = Макс(Предыдущий, ДоПредыдущего + Деньги);
		ДоПредыдущего = Предыдущий;
		Предыдущий = Текущий;
	КонецЦикла;
	Возврат Предыдущий;
КонецФункции
```

Здесь мы сразу храним только два последних значения ДП вместо массива — память `O(1)`.

```1C
Проверить("Грабитель", ОграбитьДома(ЧислаИзСтроки("2,7,9,3,1")), 12);
Проверить("Два дома", ОграбитьДома(ЧислаИзСтроки("5,1")), 5);
```

## Задача 5. Пути в сетке (двумерное ДП)

**Условие.** Робот стоит в левом верхнем углу сетки `Строк × Столбцов` и может ходить только **вправо** или **вниз**. Сколько разных путей до правого нижнего угла?

```text
Сетка 3 × 3, число путей до каждой клетки:
1  1  1
1  2  3
1  3  6   ← ответ 6
```

В клетку можно прийти только сверху или слева: `ДП[r][c] = ДП[r−1][c] + ДП[r][c−1]`. В первой строке и первом столбце путь один (только прямо).

```1C
&НаКлиенте
Функция ПутейВСетке(Строк, Столбцов)
	ДП = Новый Массив(Строк, Столбцов);   // двумерный массив Строк × Столбцов
	Для r = 0 По Строк - 1 Цикл
		Для c = 0 По Столбцов - 1 Цикл
			Если r = 0 Или c = 0 Тогда
				ДП[r][c] = 1;
			Иначе
				ДП[r][c] = ДП[r - 1][c] + ДП[r][c - 1];
			КонецЕсли;
		КонецЦикла;
	КонецЦикла;
	Возврат ДП[Строк - 1][Столбцов - 1];
КонецФункции
```

`Новый Массив(Строк, Столбцов)` создаёт массив массивов: `ДП[r]` — строка, `ДП[r][c]` — клетка. Время и память `O(Строк × Столбцов)`.

```1C
Проверить("Сетка 3×3", ПутейВСетке(3, 3), 6);
Проверить("Сетка 3×7", ПутейВСетке(3, 7), 28);
```

## Как узнать задачу на ДП

| Признак в условии | Пример |
| --- | --- |
| «Сколько способов…» | Лестница, пути в сетке |
| «Максимальная / минимальная сумма, стоимость, длина» с выбором на каждом шаге | Грабитель, рюкзак |
| Решение для `n` складывается из решений для меньших `n` | Почти все задачи ДП |
| Наивная рекурсия пересчитывает одно и то же | Фибоначчи |

> [!tip] Если не получается
> Начните с рекурсивного перебора «как бы я решал для маленького `n`», затем добавьте мемоизацию ([[12. Рекурсия]]) — это уже ДП. Переписать мемоизацию в цикл с массивом можно потом.

> [!question]- Проверь себя
> 1. На какие четыре вопроса нужно ответить, чтобы решить задачу на ДП?
> 2. Почему в задаче о лестнице `ДП[i] = ДП[i−1] + ДП[i−2]`?
> 3. Что хранит переменная `ЛучшийЗдесь` в алгоритме Кадане и когда подмассив «начинается заново»?
> 4. Почему в Кадане нельзя начинать с `Ответ = 0`?
> 5. Как сократить память в задаче о лестнице до `O(1)`?
>
> > [!success]- Ответы
> > 1. Смысл состояния `ДП[i]`, переход, база, где ответ.
> > 2. На ступеньку `i` попадаем либо с `i−1` шагом, либо с `i−2` прыжком; способы складываются.
> > 3. Максимальную сумму подмассива, заканчивающегося на текущем элементе. Заново — когда сам элемент больше, чем продолжение (накопленный хвост отрицательный).
> > 4. Если все числа отрицательные, ответ 0 будет неверным — непустого подмассива с суммой 0 нет.
> > 5. Хранить только два последних значения в переменных вместо всего массива.
