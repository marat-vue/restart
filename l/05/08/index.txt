<h2 id="что-такое-xml-и-зачем-он-нужен">Что такое XML и зачем он нужен</h2>
<p><strong>XML</strong> — текстовый формат для обмена данными между программами. Данные записываются в виде вложенных <strong>элементов</strong> с тегами:</p>

<p>XML — «старший брат» JSON: многословнее, но строже. Его используют банки, налоговая (электронная отчётность), обмены между базами 1С, многие государственные сервисы. Junior-разработчику часто достаются задачи «выгрузить в XML» и «загрузить из XML».</p>
<p>В 1С с XML работают двумя способами:</p>
<ul>
<li><strong>потоково</strong> — <code>ЗаписьXML</code> и <code>ЧтениеXML</code>: пишем и читаем элемент за элементом, как книгу по строчкам. Подходит для файлов любого размера;</li>
<li><strong>через XDTO</strong> — сериализация: объект 1С целиком превращается в XML и обратно.</li>
</ul>

<span data-line=""><span style="color:var(--shiki-foreground)">		Код </span><span style="color:var(--shiki-token-keyword)">=</span><span style="color:var(--shiki-foreground)"> Чтение.ЗначениеАтрибута(</span><span style="color:var(--shiki-token-string-expression)">"Код"</span><span style="color:var(--shiki-foreground)">)</span><span style="color:var(--shiki-token-keyword)">;</span></span>
<span data-line=""><span style="color:var(--shiki-foreground)">		Чтение.Прочитать()</span><span style="color:var(--shiki-token-keyword)">;</span><span style="color:var(--shiki-token-comment)">                          // переходим к текстовому узлу</span></span>

<span data-line=""><span style="color:var(--shiki-token-comment)">		// ... найти или создать товар по коду</span></span>
<span data-line=""><span style="color:var(--shiki-token-keyword)">	КонецЕсли;</span></span>

<span data-line=""><span style="color:var(--shiki-foreground)">Чтение.Закрыть()</span><span style="color:var(--shiki-token-keyword)">;</span></span></code></pre></figure>
<p><code>ЧтениеXML</code> — курсор: <code>Прочитать()</code> переходит к следующему узлу (начало элемента, текст, конец элемента). Так читается файл любого размера без загрузки целиком в память.</p>
<p>Показанный читатель рассчитан только на простой формат <code>&#x3C;Товар Код="…">текст&#x3C;/Товар></code> из примера записи. Для произвольного XML одного <code>Прочитать()</code> недостаточно: текст может быть разбит на несколько узлов, а элемент — пустым или вложенным. В рабочем загрузчике накапливайте текст до соответствующего конца элемента и проверяйте атрибуты перед созданием объекта.</p>
<div class="callout callout-tip" data-callout="tip">
<div class="callout-title">DOM для небольших файлов</div>
<div class="callout-body"><p>Для небольших документов удобнее модель DOM: <code>ПостроительDOM.Прочитать(Чтение)</code> → <code>ДокументDOM</code> → поиск через <code>ПолучитьЭлементыПоИмени()</code>. Для больших — только потоковое чтение.</p></div>
</div>

<p>Так устроена выгрузка «один в один» между базами с одинаковой конфигурацией. Для обмена по чужой схеме (XSD от партнёра) импортируют <strong>XDTO-пакет</strong> (Общие → XDTO-пакеты) и работают с объектами <code>ФабрикаXDTO</code>.</p>
<p><img src="/restart/vault/%D0%9A%D0%B0%D1%80%D1%82%D0%B8%D0%BD%D0%BA%D0%B8/05.%20%D0%9F%D1%80%D0%BE%D1%84%D0%B5%D1%81%D1%81%D0%B8%D0%BE%D0%BD%D0%B0%D0%BB%D1%8C%D0%BD%D0%B0%D1%8F%20%D1%80%D0%B0%D0%B7%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%BA%D0%B0/08-%D0%98%D0%BC%D0%BF%D0%BE%D1%80%D1%82-XDTO.png" alt="08-Импорт-XDTO.png" loading="lazy" decoding="async"></p>
<p><em>Контекстное меню ветки <code>XDTO-пакеты</code>: «Импорт XML-схемы…» — точка входа для схемы XSD партнёра. Для потокового чтения простого XML из начала темы импорт XSD не требуется.</em></p>
<p><code>ПрочитатьXML</code> восстанавливает значение в памяти, а не сохраняет объект в базе. После чтения нужны сопоставление ссылок, проверки и явная запись; одинаковая структура конфигураций сама по себе не гарантирует наличие объектов, на которые ссылается XML.</p>
<h2 id="правила-загрузки-данных">Правила загрузки данных</h2>

































<div class="table-wrap"><table><thead><tr><th>Правило</th><th>Почему</th></tr></thead><tbody><tr><td>Сопоставление по <strong>ключу</strong> (код, ИНН, GUID), а не по наименованию</td><td>Наименования не уникальны</td></tr><tr><td>Повторная загрузка не создаёт дубли</td><td>Сначала ищем существующий объект</td></tr><tr><td>Проверка значений до записи</td><td>Отрицательное количество, неизвестный товар</td></tr><tr><td>Порция + транзакция на порцию</td><td>Ошибка в одной записи не «роняет» всю загрузку и не держит длинную транзакцию</td></tr><tr><td>Протокол</td><td>Что загружено, что пропущено и почему</td></tr><tr><td><code>ОбменДанными.Загрузка = Истина</code> при массовой загрузке</td><td>Устанавливает признак загрузки. Прикладные проверки пропускаются, только если сами обработчики и подписки проверяют этот признак; целостность загружаемых данных обеспечивает вызывающий код</td></tr></tbody></table></div>
<p>Флаг <strong>не отключает произвольный код автоматически</strong>. Типичный обработчик сам делает ранний выход <code>Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;</code>. Это правило и ответственность загрузчика описаны в <a href="https://kb.1ci.com/1C_Enterprise_Platform/Guides/Developer_Guides/1C_Enterprise_Development_Standards/Creating_and_modifying_metadata_objects/Object_event_handlers/DataExchange.Load_flag_in_object_event_handlers/" target="_blank" rel="noopener noreferrer">стандарте 1С</a>.</p>
