XML и обмен данными

Коротко

XML пишут потоково ЗаписьXML (ЗаписатьНачалоЭлемента → ЗаписатьАтрибут → ЗаписатьТекст → ЗаписатьКонецЭлемента) и читают ЧтениеXML в цикле Пока Чтение.Прочитать() по ТипУзла. Для объектов 1С есть сериализация XDTO (СериализаторXDTO). Регулярный обмен между базами строят на планах обмена и готовых механизмах (Конвертация данных, EnterpriseData), а не на «ручной выгрузке».

Что такое XML и зачем он нужен

XML — текстовый формат для обмена данными между программами. Данные записываются в виде вложенных элементов с тегами:

ЧастьПримерСмысл
Элемент<Товар>…</Товар>Единица данных: открывающий и закрывающий тег
АтрибутКод="000000001"Дополнительное свойство элемента
ТекстЧайникЗначение внутри элемента
Вложенность<Товары> содержит <Товар>Структура: список внутри списка

XML — «старший брат» JSON: многословнее, но строже. Его используют банки, налоговая (электронная отчётность), обмены между базами 1С, многие государственные сервисы. Junior-разработчику часто достаются задачи «выгрузить в XML» и «загрузить из XML».

В 1С с XML работают двумя способами:

  • потоково — ЗаписьXML и ЧтениеXML: пишем и читаем элемент за элементом, как книгу по строчкам. Подходит для файлов любого размера;
  • через XDTO — сериализация: объект 1С целиком превращается в XML и обратно.

Запись XML

Результат:

XMLСтрока() даёт каноническое представление значения (дата — ISO, число — с точкой, булево — true/false); обратно — XMLЗначение(Тип("Дата"), Строка).

Чтение XML

ЧтениеXML — курсор: Прочитать() переходит к следующему узлу (начало элемента, текст, конец элемента). Так читается файл любого размера без загрузки целиком в память.

Показанный читатель рассчитан только на простой формат <Товар Код="…">текст</Товар> из примера записи. Для произвольного XML одного Прочитать() недостаточно: текст может быть разбит на несколько узлов, а элемент — пустым или вложенным. В рабочем загрузчике накапливайте текст до соответствующего конца элемента и проверяйте атрибуты перед созданием объекта.

DOM для небольших файлов

Для небольших документов удобнее модель DOM: ПостроительDOM.Прочитать(Чтение) → ДокументDOM → поиск через ПолучитьЭлементыПоИмени(). Для больших — только потоковое чтение.

XDTO: объекты 1С ↔ XML

Так устроена выгрузка «один в один» между базами с одинаковой конфигурацией. Для обмена по чужой схеме (XSD от партнёра) импортируют XDTO-пакет (Общие → XDTO-пакеты) и работают с объектами ФабрикаXDTO.

Контекстное меню ветки XDTO-пакеты: «Импорт XML-схемы…» — точка входа для схемы XSD партнёра. Для потокового чтения простого XML из начала темы импорт XSD не требуется.

ПрочитатьXML восстанавливает значение в памяти, а не сохраняет объект в базе. После чтения нужны сопоставление ссылок, проверки и явная запись; одинаковая структура конфигураций сама по себе не гарантирует наличие объектов, на которые ссылается XML.

Правила загрузки данных

ПравилоПочему
Сопоставление по ключу (код, ИНН, GUID), а не по наименованиюНаименования не уникальны
Повторная загрузка не создаёт дублиСначала ищем существующий объект
Проверка значений до записиОтрицательное количество, неизвестный товар
Порция + транзакция на порциюОшибка в одной записи не «роняет» всю загрузку и не держит длинную транзакцию
ПротоколЧто загружено, что пропущено и почему
ОбменДанными.Загрузка = Истина при массовой загрузкеУстанавливает признак загрузки. Прикладные проверки пропускаются, только если сами обработчики и подписки проверяют этот признак; целостность загружаемых данных обеспечивает вызывающий код

Флаг не отключает произвольный код автоматически. Типичный обработчик сам делает ранний выход Если ОбменДанными.Загрузка Тогда Возврат; КонецЕсли;. Это правило и ответственность загрузчика описаны в стандарте 1С.

Junior-разработчику чаще всего достаются доработки готовых правил обмена в типовых конфигурациях — поэтому важно понимать регистрацию изменений и сопоставление объектов, а не писать обмен с нуля.

Проверь себя

  1. Почему XML большого размера читают ЧтениеXML, а не DOM?

  2. Как избежать дублей при повторной загрузке?

  3. Зачем нужен план обмена, если можно просто выгрузить все товары?

Ответы
  1. Потоковое чтение не загружает документ целиком в память.
  2. Искать существующий объект по устойчивому ключу (код, GUID) перед созданием.
  3. Он регистрирует изменения — выгружаются только изменённые объекты, и известно, что уже передано.
