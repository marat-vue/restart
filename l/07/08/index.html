Модульные тесты в YAxUnit

Коротко

YAxUnit — открытый фреймворк модульного тестирования для 1С. Устанавливается как расширение конфигурации; тесты пишутся в общих модулях (обычно в отдельном расширении с тестами). В модуле — экспортная процедура ИсполняемыеСценарии(), где тесты регистрируются через ЮТТесты.ДобавитьТест("ИмяТеста"), и экспортные процедуры-тесты. Проверки пишутся «текучим» синтаксисом: ЮТест.ОжидаетЧто(Результат).Равно(300). Запуск — из интерфейса YAxUnit в 1С:Предприятии, из EDT или командной строкой с параметром /C RunUnitTests=…; результат — отчёт с зелёными и красными тестами, который понимают CI-системы.

Зачем фреймворк, если тесты можно написать самому

В прошлом уроке мы сделали тестовую обработку с процедурой ПроверитьРавенство() и счётчиками (07. Модульные тесты своими руками). Для учёбы это отлично, но в реальном проекте быстро понадобится больше:

НужноСвоя обработкаФреймворк
Десятки видов проверок: равно, заполнено, тип, содержит, исключениеПисать самомуГотово
Тесты с разными параметрамиКопировать тестыОдин тест + набор параметров
Отчёт для CI (JUnit, Allure)Писать самомуГотово
Запуск только упавших / одного модуляНетЕсть
Подготовка и откат данныхСамомуВспомогательные методы

YAxUnit — популярный открытый фреймворк от сообщества 1С-разработчиков (проект bia-technologies на GitHub). Документация: bia-technologies.github.io/yaxunit.

ЧастьЧто это
Расширение YAxUnit«Движок»: находит тестовые модули, запускает тесты, строит отчёт. Скачивается из релизов проекта и загружается в базу как расширение (04. Расширения)

Тестовые модулиОбщие модули с префиксом, например ОМ_РасчетыКлиентСервер — тесты для модуля РасчетыКлиентСервер
Безопасный режим

После загрузки расширения YAxUnit в базу у него нужно отключить безопасный режим и защиту от опасных действий — так требует документация фреймворка. Делайте это только в тестовой базе.

Первый тест

Тестируем функции из прошлого урока — РасчетыКлиентСервер.РассчитатьСуммуСтроки и СуммаСоСкидкой.

Создаём в расширении с тестами общий модуль ОМ_РасчетыКлиентСервер (флажки «Клиент» и «Сервер» — чтобы тесты могли выполняться в обоих контекстах) и пишем:

Разберём:

КодСмысл
ИсполняемыеСценарии()Обязательная экспортная процедура: здесь перечислены тесты модуля
ЮТТесты.ДобавитьТест("Имя")Зарегистрировать тест; имя совпадает с именем экспортной процедуры
.СПараметрами(99, 10, 990)Запустить тот же тест с другими параметрами — каждая строка становится отдельным тестом. Удобно для граничных значений (04. Техники тест-дизайна)
ЮТест.ОжидаетЧто(Результат)«Ожидается, что значение…» — начало проверки
.Равно(300)«…равно 300». Не равно — тест падает с понятным сообщением

Точки в начале строк (.ДобавитьТест, .СПараметрами) — это цепочка вызовов: каждый метод возвращает объект, у которого вызывается следующий. Такой стиль называют «текучим» (fluent): код читается почти как фраза.

Какие бывают проверки

После ЮТест.ОжидаетЧто(Значение) можно вызывать разные утверждения и даже соединять их в цепочку:

ПроверкаСмысл
.Равно(X) / .НеРавно(X)Значение равно / не равно X
.Заполнено() / .НеЗаполнено()Значение заполнено (как ЗначениеЗаполнено)
.ИмеетТип("Число")Тип значения
.Больше(X), .Меньше(X)Сравнение
.Содержит(X)Строка или коллекция содержит X
.ИмеетДлину(N)Длина строки или размер коллекции

Полный список утверждений — в документации YAxUnit; при наборе кода в EDT или Конфигураторе после точки работает подсказка.

Один тест — одно поведение

Как и тест-кейс (05. Тест-кейсы и баг-репорты), модульный тест проверяет одну вещь. Если тест называется СуммаСтроки_Округление, в нём не должно быть проверок скидки. Тогда по имени упавшего теста сразу ясно, что сломалось.

Как запустить

СпособКакКогда удобно
Из 1С:ПредприятияКоманда «Запуск тестирования» в интерфейсе YAxUnitУчёба, отладка
Из 1C:EDTПлагин: значок запуска рядом с тестом, Ctrl+Shift+TЕжедневная разработка в EDT
Командная строка1cv8c.exe ENTERPRISE /IBName ТестоваяБаза /N Admin /C RunUnitTests=C:\tmp\test-config.jsonАвтоматический запуск, CI (14. Регрессия, отчёты и запуск без участия человека)

Файл test-config.json описывает, какие тесты запускать и куда сохранить отчёт. Его можно собрать в форме настроек YAxUnit.

После запуска YAxUnit показывает дерево тестов: зелёные — пройдены, красные — упали, с текстом ошибки вида «ожидали, что 37.035 равно 37.04».

Тесты с базой данных

Модульные тесты чистых функций — самые простые. Для тестов, которые создают справочники и документы, во фреймворке есть вспомогательные средства: создание тестовых данных и выполнение теста в транзакции с откатом — по той же идее, что в нашем интеграционном тесте проведения (07. Модульные тесты своими руками). Подробности — в разделе документации о тестовых данных.

Учебная платформа

YAxUnit — расширение, поэтому его можно загрузить и в учебную базу. Но точная совместимость с версией платформы и режимом совместимости конфигурации указана в документации фреймворка — проверьте её перед установкой. Своя тестовая обработка из урока 07 работает на любой платформе.

Проверь себя

  1. Как YAxUnit устанавливается в базу и где принято хранить тесты?

  2. Зачем нужна процедура ИсполняемыеСценарии()?

  3. Как одним тестом проверить три граничных значения?

  4. Как запустить тесты без участия человека?

Ответы
  1. Как расширение конфигурации; тесты — в общих модулях отдельного расширения, чтобы не смешивать их с рабочим кодом.
  2. В ней регистрируются тесты модуля через ЮТТесты.ДобавитьТест; фреймворк вызывает её, чтобы узнать, что запускать.
  3. Зарегистрировать тест с несколькими вызовами .СПараметрами(…) — каждый набор параметров станет отдельным тестом.
  4. Командной строкой: запуск 1С:Предприятия с параметром /C RunUnitTests=путь к файлу настроек.
