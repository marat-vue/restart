<h2 id="из-чего-собирается-сценарий">Из чего собирается сценарий</h2>
<p>Почти любой UI-сценарий состоит из трёх видов шагов:</p>

























<div class="table-wrap"><table><thead><tr><th>Вид</th><th>Примеры</th><th>Доля в сценарии</th></tr></thead><tbody><tr><td><strong>Навигация</strong></td><td>Открыть раздел, создать документ, перейти на вкладку</td><td>Небольшая</td></tr><tr><td><strong>Ввод</strong></td><td>Выбрать значение в поле, ввести число, добавить строку таблицы, нажать кнопку</td><td>Основная</td></tr><tr><td><strong>Проверка</strong></td><td>Открылось окно, поле равно значению, таблица равна ожидаемой, есть сообщение</td><td><strong>Обязательная</strong></td></tr></tbody></table></div>

<h2 id="как-найти-нужный-шаг">Как найти нужный шаг</h2>
<p>Запоминать сотни формулировок не нужно.</p>
<p><strong>Способ 1. Поиск известных шагов.</strong> В Vanessa Automation есть окно поиска по библиотеке шагов: вводите ключевое слово («таблица», «поле», «кнопк») — видите список подходящих шагов с описанием, выбираете и вставляете в сценарий, заменяя параметры в кавычках на свои.</p>
<p><strong>Способ 2. Запись действий пользователя.</strong> Самый быстрый путь для новичка:</p>
<pre><pre class="mermaid-source">flowchart LR
    A["Включить запись&#x3C;br/>в Vanessa Automation"] --> B["Выполнить действия руками&#x3C;br/>в клиенте тестирования"]
    B --> C["Остановить запись"]
    C --> D["Получить готовые шаги&#x3C;br/>Gherkin"]
    D --> E["Добавить проверки&#x3C;br/>и почистить лишнее"]
</pre></pre>
<ol>
<li>Подключите клиент тестирования.</li>
<li>В VA включите <strong>запись действий</strong>.</li>
<li>В окне клиента выполните сценарий руками: откройте раздел, создайте накладную, заполните поля.</li>
<li>Остановите запись — VA сформирует текст шагов.</li>
<li>Обязательно <strong>доработайте</strong> запись: добавьте проверки «Тогда …» (запись фиксирует только действия), удалите случайные щелчки, замените заголовки на имена элементов там, где это надёжнее.</li>
</ol>
<p>Запись экономит время на «механике», а думать над проверками всё равно приходится самому.</p>
<h2 id="переменные-запомнить-и-использовать">Переменные: запомнить и использовать</h2>
<p>Часто значение становится известным только во время прогона — например, <strong>номер</strong> только что записанного документа. Его можно запомнить и использовать дальше:</p>

<h2 id="свои-шаги">Свои шаги</h2>
<p>Стандартные шаги описывают <strong>интерфейс</strong>: кнопки, поля, таблицы. Но сценарий из десятков интерфейсных шагов тяжело читать, а одни и те же действия («создать накладную с товаром…») повторяются во многих сценариях. Поэтому создают <strong>свои шаги</strong> на языке бизнеса.</p>
<h3 id="способ-1-экспортный-сценарий">Способ 1. Экспортный сценарий</h3>
<p>Сценарий можно пометить меткой <code>@ExportScenarios</code> — тогда его <strong>название</strong> становится новым шагом, который можно вызывать из других сценариев:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="gherkin" data-theme="mono"><code data-language="gherkin" data-theme="mono" style="display: grid;"><span data-line=""><span style="color:var(--shiki-token-comment)">#language: ru</span></span>
<span data-line=""><span style="color:var(--shiki-token-function)">@ExportScenarios</span></span>
<span data-line=""><span style="color:var(--shiki-token-function)">@IgnoreOnCIMainBuild</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:var(--shiki-token-keyword)">Функционал</span><span style="color:var(--shiki-foreground)">:</span><span style="color:var(--shiki-token-string)"> Общие шаги для продаж</span></span>
<span data-line=""> </span>
<span data-line=""><span style="color:var(--shiki-token-keyword)">Сценарий</span><span style="color:var(--shiki-foreground)">:</span><span style="color:var(--shiki-token-string)"> Я создаю расходную накладную для покупателя "Покупатель"</span></span>
<span data-line=""><span style="color:var(--shiki-token-keyword)">	Когда </span><span style="color:var(--shiki-foreground)">В командном интерфейсе я выбираю </span><span style="color:var(--shiki-token-string-expression)">'Торговый учёт'</span><span style="color:var(--shiki-token-string-expression)"> 'Расходные накладные'</span></span>
<span data-line=""><span style="color:var(--shiki-token-keyword)">	И </span><span style="color:var(--shiki-foreground)">я нажимаю на кнопку с именем </span><span style="color:var(--shiki-token-string-expression)">'ФормаСоздать'</span></span>
<span data-line=""><span style="color:var(--shiki-token-keyword)">	И </span><span style="color:var(--shiki-foreground)">из выпадающего списка с именем </span><span style="color:var(--shiki-token-string-expression)">"Покупатель"</span><span style="color:var(--shiki-foreground)"> я выбираю по строке </span><span style="color:var(--shiki-token-string-expression)">'[Покупатель]'</span></span></code></pre></figure>
<p>Теперь в любом сценарии можно написать одну строку:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="gherkin" data-theme="mono"><code data-language="gherkin" data-theme="mono" style="display: grid;"><span data-line=""><span style="color:var(--shiki-token-keyword)">Дано </span><span style="color:var(--shiki-foreground)">Я создаю расходную накладную для покупателя </span><span style="color:var(--shiki-token-string-expression)">"Ромашка"</span></span></code></pre></figure>
<p>Параметр в кавычках подставится вместо <code>[Покупатель]</code>. Метка <code>@IgnoreOnCIMainBuild</code> говорит: сам этот файл как тест не запускать — это библиотека шагов. Подробно о механизме — в документации VA.</p>
<h3 id="способ-2-шаг-на-встроенном-языке">Способ 2. Шаг на встроенном языке</h3>
<p>Для шагов, которые удобнее сделать кодом (быстро создать данные, проверить движения регистра), VA умеет сгенерировать <strong>обработку-шаблон</strong> к <code>.feature</code>-файлу: для каждого нереализованного шага создаётся экспортная процедура, в которую пишется код на встроенном языке. Например, шаг «в базе есть товар "Чайник"» может проверять справочник и при необходимости создавать элемент. Это мощно, но требует программирования — начинайте со стандартных и экспортных сценариев.</p>
<h2 id="как-сделать-сценарий-надёжным">Как сделать сценарий надёжным</h2>

































<div class="table-wrap"><table><thead><tr><th>Правило</th><th>Почему</th></tr></thead><tbody><tr><td>Ищите элементы по <strong>имени</strong>, а не по заголовку</td><td>Заголовки меняются</td></tr><tr><td>После каждого важного действия — проверка</td><td>Падение в месте причины</td></tr><tr><td>Начинайте с «закрыть все окна»</td><td>Независимость от прошлого состояния</td></tr><tr><td>Не полагайтесь на позицию строки («третья строка»)</td><td>Порядок может измениться — ищите строку по значениям</td></tr><tr><td>Не используйте фиксированные паузы «подождать 5 секунд»</td><td>Медленно и ненадёжно; используйте шаги, которые ждут появления окна или значения</td></tr><tr><td>Один сценарий — одно поведение</td><td>Понятно, что именно сломалось</td></tr></tbody></table></div>
<details class="callout callout-question" data-callout="question">
<summary class="callout-title">Проверь себя</summary>
<div class="callout-body"><ol>
<li>
<p>Какие три вида шагов составляют UI-сценарий и какой из них обязателен для того, чтобы сценарий был тестом?</p>
</li>
<li>
<p>Чем отличаются проверки «таблица стала равной» и «таблица содержит строки»?</p>
</li>
<li>
<p>Что нужно обязательно сделать после записи действий пользователя?</p>
</li>
<li>
<p>Как использовать номер документа, известный только во время прогона?</p>
</li>
<li>
<p>Зачем нужны экспортные сценарии?</p>
</li>
</ol><details class="callout callout-success" data-callout="success">
<summary class="callout-title">Ответы</summary>
<div class="callout-body"><ol>
<li>Навигация, ввод, проверка; без проверок сценарий ничего не тестирует.</li>
<li>«Стала равной» требует полного совпадения таблицы; «содержит строки» — только наличия указанных строк.</li>
<li>Добавить проверки «Тогда …», убрать лишние действия, при необходимости заменить заголовки на имена элементов.</li>
<li>Запомнить его шагом «я запоминаю значение поля … как "Имя"» и подставлять как <code>$Имя$</code>.</li>
<li>Чтобы повторяющиеся действия оформить одним бизнес-шагом и вызывать из многих сценариев.</li>
</ol></div>
