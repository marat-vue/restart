Соответствие как хеш-таблица

Коротко

Соответствие в 1С — это хеш-таблица: хранит пары «ключ → значение» и находит значение по ключу за O(1) в среднем, не перебирая все элементы. Это главный инструмент ускорения: «поиск в цикле» за O(n) превращается в мгновенную проверку, и решение O(n²) становится O(n). Типовые применения: подсчёт частот, множество уже встреченных значений, индекс «значение → позиция» (задача о двух слагаемых), группировка (анаграммы).

Что такое хеш-таблица простыми словами

Представьте гардероб. Вы сдаёте пальто и получаете номерок. Когда возвращаетесь, гардеробщик не перебирает все пальто подряд — он идёт сразу к крючку с вашим номером. Номерок — ключ, пальто — значение.

Хеш-таблица работает так же: по ключу она сразу вычисляет «номер крючка», где лежит значение. Поэтому поиск не зависит от того, сколько всего элементов хранится: и при 10, и при миллионе — примерно одинаково быстро.

Ключом может быть строка, число, дата, ссылка — любое значение, которое можно сравнить.

Ловушка: значение, равное

Неопределено Получить() возвращает Неопределено и когда ключа нет, и когда по ключу записано Неопределено. В задачах храним осмысленные значения (числа, Истина), чтобы не путать эти случаи.

Шаблон 1. Подсчёт частот

Задача: сколько раз встречается каждое значение. ["яблоко", "груша", "яблоко"] → яблоко: 2, груша: 1.

Время O(n). Этот шаблон встречается настолько часто, что его стоит знать наизусть.

Применение — первый неповторяющийся символ (задача из прошлого урока): "абракадабра" → "к".

Второй проход идёт по строке, а не по соответствию: так мы найдём именно первый по порядку символ — порядок обхода соответствия не гарантирован. Два прохода по n — всё равно O(n).

Шаблон 2. Множество: «видели ли мы это раньше?»

Отдельного типа «множество» во встроенном языке нет — используем соответствие со значением Истина.

Задача: есть ли в массиве повторяющиеся элементы? [1, 2, 3, 1] → Истина.

Простое решение — два вложенных цикла, O(n²) (02. Сложность алгоритмов). С множеством — один проход:

ШагЭлементВстречались до шагаРезультат
11{}запомнили 1
22{1}запомнили 2
33{1, 2}запомнили 3
41{1, 2, 3}1 уже есть → Истина

Время O(n), память O(n) — классический обмен памяти на скорость.

Шаблон 3. Индекс «значение → позиция»: задача о двух слагаемых

Это, пожалуй, самая известная задача собеседований.

Условие. Дан массив чисел и число Цель. Найти индексы двух разных элементов, сумма которых равна Цель. Гарантируется, что ответ ровно один.

Числа = [2, 7, 11, 15], Цель = 9 → индексы 0, 1 (2 + 7 = 9).

Простое решение — перебрать все пары: O(n²).

Быстрое решение. Для каждого числа Х нам нужна «пара» — Цель − Х. Вопрос «встречалась ли уже пара?» — это поиск в соответствии за O(1). Храним «значение → его индекс»:

Прогон: [2, 7, 11, 15], Цель = 9:

iЧисла[i]Ищем паруВ соответствииДействие
027{}нет; запоминаем 2 → 0
172{2→0}нашли 2 на индексе 0 → ответ [0, 1]

Почему запоминаем после проверки? Иначе при Числа = [3, 5], Цель = 6 число 3 найдёт «пару» само в себе. А по условию нужны два разных элемента.

Время O(n), память O(n).

Шаблон 4. Группировка: анаграммы

Анаграммы — слова из одних и тех же букв: «кот» и «ток», «пила» и «липа».

Задача 1: являются ли две строки анаграммами? Посчитаем частоты букв в первой строке, вычтем частоты второй — в итоге все счётчики должны стать нулями.

Время O(n). Альтернатива — отсортировать буквы обеих строк и сравнить: O(n log n).

Задача 2: сгруппировать слова-анаграммы. ["кот", "ток", "пила", "липа", "сон"] → [кот, ток], [пила, липа], [сон].

Идея: у всех анаграмм одинаковый «ключ» — буквы, отсортированные по алфавиту («кот» и «ток» → «кот»). Группируем по ключу в соответствии «ключ → массив слов»:

Сортировку букв делаем через СписокЗначений.СортироватьПоЗначению() — у массива в 1С нет метода сортировки (подробнее — 09. Сортировки).

Когда соответствие — правильный выбор

Ищите в условии задачи слова-подсказки:

Подсказка в задачеПриём
«сколько раз встречается», «самый частый»Подсчёт частот
«есть ли повторы», «уникальные элементы»Множество
«найти пару с суммой / разницей»Индекс «значение → позиция»
«сгруппировать по признаку»Соответствие «ключ → массив»
Проверь себя

  1. Почему поиск в соответствии быстрее, чем Массив.Найти()?

  2. Как реализовать «множество» во встроенном языке?

  3. В задаче о двух слагаемых — почему значение кладём в соответствие после проверки, а не до?

  4. Почему при поиске первого уникального символа второй проход идёт по строке, а не по соответствию?

Ответы
  1. Соответствие — хеш-таблица: по ключу сразу вычисляется место хранения, без перебора; O(1) в среднем против O(n).
  2. Соответствие, где ключ — элемент, а значение — Истина.
  3. Чтобы элемент не нашёл «пару» сам в себе (когда Цель = 2 × элемент).
  4. Порядок обхода соответствия не гарантирован, а нужен первый символ в порядке строки.
