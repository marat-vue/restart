<div class="callout-body"><p>Проверку делаем на двух уровнях: <strong>в форме</strong> — чтобы подсказать пользователю до записи, <strong>в <code>ПередЗаписью</code> модуля объекта</strong> — чтобы запретить некорректную запись и из формы, и из кода (<code>Отказ = Истина</code>). <code>ОбработкаПроверкиЗаполнения</code> вызывается механизмом проверки заполнения, а не каждым программным <code>Записать()</code>. Сообщение к полю: <code>СообщениеПользователю</code> с <code>Поле</code> и <code>ПутьКДанным</code>/<code>УстановитьДанные()</code>.</p></div>

<h2 id="зачем-проверять-дважды">Зачем проверять дважды</h2>
<p>Правила нашей накладной: покупатель обязателен; в каждой строке товаров выбран товар, количество больше нуля, цена не отрицательная. Пустую табличную часть <code>Товары</code> не запрещаем — в накладной могут быть только услуги.</p>
<p>Проверять будем на <strong>двух уровнях</strong>, и у каждого своя роль:</p>























<div class="table-wrap"><table><thead><tr><th>Уровень</th><th>Где</th><th>Задача</th><th>Аналогия</th></tr></thead><tbody><tr><td><strong>Форма</strong></td><td>Модуль формы, на клиенте</td><td><strong>Подсказать</strong> пользователю до записи, подсветить поле с ошибкой</td><td>Продавец на кассе: «Вы забыли пакет»</td></tr><tr><td><strong>Объект</strong></td><td>Модуль объекта, <code>ПередЗаписью</code></td><td><strong>Запретить</strong> запись неверных данных — из формы, из обработки, из обмена</td><td>Охранник на выходе: без чека не выпустит</td></tr></tbody></table></div>
<p>Проверки в форме удобны, но обходятся: документ можно записать без формы (кодом, загрузкой). Поэтому <strong>обязательное</strong> правило всегда дублируем в модуле объекта. Проверки в форме — для удобства, в объекте — для гарантии.</p>
<h2 id="заполненность--правильность">Заполненность ≠ правильность</h2>
<p>У реквизита в конфигурации есть свойство <strong>«Проверка заполнения: Выдавать ошибку»</strong> (<a href="/restart/l/01/22/" data-internal="true">22. Предопределённые данные и заполнение</a>). Оно проверяет только «не пусто». Количество −5 — заполнено, но недопустимо. Поэтому для правил вида «больше нуля» нужен свой код.</p>
<p>Красное подчёркивание пустого поля в форме — только подсказка интерфейса. Программный <code>Записать()</code> не обязан выполнять проверки формы. Подробнее — <a href="https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/?sphrase_id=1808293" target="_blank" rel="noopener noreferrer">руководство 1С, 5.6.12</a>.</p>
<h2 id="сообщение-привязанное-к-полю">Сообщение, привязанное к полю</h2>

<p>Отличия от проверки в форме:</p>






























<div class="table-wrap"><table><thead><tr><th></th><th>В форме</th><th>В модуле объекта</th></tr></thead><tbody><tr><td>Доступ к данным</td><td><code>Объект.Покупатель</code></td><td><code>Покупатель</code> — напрямую</td></tr><tr><td>Номер строки</td><td>Вычисляем через <code>Индекс()</code></td><td>Есть стандартный <code>НомерСтроки</code> (с 1)</td></tr><tr><td>Привязка сообщения</td><td><code>ПутьКДанным = "Объект"</code></td><td><code>УстановитьДанные(ЭтотОбъект)</code> — «ошибка в этом объекте»</td></tr><tr><td>Результат ошибки</td><td>Подсказка</td><td><strong>Запись отменяется</strong>: <code>Отказ = Истина</code></td></tr></tbody></table></div>
<div class="callout callout-warning" data-callout="warning">
<div class="callout-title">Внимание</div>
<div class="callout-body"><p><code>Отказ</code>, а не <code>Возврат</code>
<code>Отказ = Истина</code> останавливает запись; один <code>Возврат</code> — <strong>нет</strong>, документ запишется. <code>Отказ = Ложь</code> никогда не пишем: его могла выставить другая проверка. Существующий <code>ПередЗаписью</code> дополняем, а не создаём второй.</p></div>
</div>
<div class="callout callout-tip" data-callout="tip">
<div class="callout-title">Альтернатива —</div>
<div class="callout-body"><p><code>ОбработкаПроверкиЗаполнения</code>
Это событие модуля объекта вызывается при интерактивной записи и при явном <code>ПроверитьЗаполнение()</code>; в нём удобно добавлять свои проверки к стандартной «Проверке заполнения» реквизитов. При программной записи документа <strong>без проведения</strong> (<code>Записать()</code> или <code>Записать(РежимЗаписиДокумента.Запись)</code>) оно само не вызывается; при программном проведении (<code>РежимЗаписиДокумента.Проведение</code>) платформа проверку заполнения выполняет. Для правил, которые должны действовать при <strong>любой</strong> записи, надёжнее <code>ПередЗаписью</code>.</p></div>
</div>
<h2 id="проверяем-по-очереди">Проверяем по очереди</h2>
<ol>
<li>Пустой покупатель → «Проверить» → сообщение; щёлкните по нему — курсор перейдёт к полю покупателя.</li>
<li>Строка без товара → сообщение у колонки товара.</li>
<li>Количество 0 → сообщение о количестве.</li>
<li>Отрицательная цена → сообщение о цене (если тип реквизита допускает отрицательные числа).</li>
<li>Некорректная накладная, кнопка <strong>«Записать»</strong> → серверная проверка запрещает запись даже без «Проверить».</li>
</ol>
