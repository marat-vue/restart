Проверка заполнения и сообщения

Коротко

Проверку делаем на двух уровнях: в форме — чтобы подсказать пользователю до записи, в ПередЗаписью модуля объекта — чтобы запретить некорректную запись и из формы, и из кода (Отказ = Истина). ОбработкаПроверкиЗаполнения вызывается механизмом проверки заполнения, а не каждым программным Записать(). Сообщение к полю: СообщениеПользователю с Поле и ПутьКДанным/УстановитьДанные().

Зачем проверять дважды

Правила нашей накладной: покупатель обязателен; в каждой строке товаров выбран товар, количество больше нуля, цена не отрицательная. Пустую табличную часть Товары не запрещаем — в накладной могут быть только услуги.

Проверять будем на двух уровнях, и у каждого своя роль:

УровеньГдеЗадачаАналогия
ФормаМодуль формы, на клиентеПодсказать пользователю до записи, подсветить поле с ошибкойПродавец на кассе: «Вы забыли пакет»
ОбъектМодуль объекта, ПередЗаписьюЗапретить запись неверных данных — из формы, из обработки, из обменаОхранник на выходе: без чека не выпустит

Проверки в форме удобны, но обходятся: документ можно записать без формы (кодом, загрузкой). Поэтому обязательное правило всегда дублируем в модуле объекта. Проверки в форме — для удобства, в объекте — для гарантии.

Заполненность ≠ правильность

У реквизита в конфигурации есть свойство «Проверка заполнения: Выдавать ошибку» (22. Предопределённые данные и заполнение). Оно проверяет только «не пусто». Количество −5 — заполнено, но недопустимо. Поэтому для правил вида «больше нуля» нужен свой код.

Красное подчёркивание пустого поля в форме — только подсказка интерфейса. Программный Записать() не обязан выполнять проверки формы. Подробнее — руководство 1С, 5.6.12.

Сообщение, привязанное к полю

Сообщить("Текст") выводит сообщение внизу окна, но не показывает, где ошибка. Для понятного сообщения используют объект СообщениеПользователю: при щелчке по такому сообщению платформа переводит курсор на поле с ошибкой и подсвечивает его.

СвойствоЗначениеСмысл
Текст«Выберите покупателя»Что увидит пользователь
ПутьКДанным"Объект"Какой реквизит формы содержит ошибочные данные
Поле"Покупатель" или "Товары[0].Количество"Путь внутри этого реквизита — к конкретному полю или ячейке

Поле — путь к данным, а не имя элемента: "Покупатель", а не "ПолеПокупателя", и без второго Объект.. Для ячейки таблицы указываем строку в квадратных скобках: "Товары[0].Количество" — количество в первой строке. Индекс начинается с 0, а номер строки для пользователя — с 1. См. статью 1С о сообщениях.

Проверка в форме

Функция проходит по правилам и при первой ошибке показывает сообщение у нужного поля:

Разберём ключевые строки:

КодЧто делает
ЗначениеЗаполнено(Объект.Покупатель)Ложь, если покупатель не выбран (пустая ссылка)
Объект.Товары.Индекс(СтрокаТовара)Номер строки в коллекции, начиная с 0
Путь = "Товары[0]."Начало пути к ячейке этой строки
Путь + "Количество"Готовый путь: "Товары[0].Количество"
Возврат ЛожьНашли ошибку — дальше не проверяем, сообщаем о первой
Возврат ИстинаОшибок нет

Функция сообщает об ошибке и не исправляет данные молча: если подставить вместо нуля единицу, пользователь не узнает, что ошибся.

Обязательная проверка в модуле объекта

Теперь гарантия. Открываем модуль объекта документа (ПКМ по документу → «Открыть модуль объекта»). Здесь реквизиты доступны напрямую — Покупатель, Товары, без Объект., — а директив &НаКлиенте/&НаСервере нет: модуль объекта всегда выполняется на сервере.

Отличия от проверки в форме:

В формеВ модуле объекта
Доступ к даннымОбъект.ПокупательПокупатель — напрямую
Номер строкиВычисляем через Индекс()Есть стандартный НомерСтроки (с 1)
Привязка сообщенияПутьКДанным = "Объект"УстановитьДанные(ЭтотОбъект) — «ошибка в этом объекте»
Результат ошибкиПодсказкаЗапись отменяется: Отказ = Истина
Внимание

Отказ, а не Возврат Отказ = Истина останавливает запись; один Возврат — нет, документ запишется. Отказ = Ложь никогда не пишем: его могла выставить другая проверка. Существующий ПередЗаписью дополняем, а не создаём второй.

Альтернатива —

ОбработкаПроверкиЗаполнения Это событие модуля объекта вызывается при интерактивной записи и при явном ПроверитьЗаполнение(); в нём удобно добавлять свои проверки к стандартной «Проверке заполнения» реквизитов. При программной записи документа без проведения (Записать() или Записать(РежимЗаписиДокумента.Запись)) оно само не вызывается; при программном проведении (РежимЗаписиДокумента.Проведение) платформа проверку заполнения выполняет. Для правил, которые должны действовать при любой записи, надёжнее ПередЗаписью.

Проверяем по очереди

  1. Пустой покупатель → «Проверить» → сообщение; щёлкните по нему — курсор перейдёт к полю покупателя.
  2. Строка без товара → сообщение у колонки товара.
  3. Количество 0 → сообщение о количестве.
  4. Отрицательная цена → сообщение о цене (если тип реквизита допускает отрицательные числа).
  5. Некорректная накладная, кнопка «Записать» → серверная проверка запрещает запись даже без «Проверить».

Сообщение есть, а документ записался — ищите, где не установлен Отказ. Поле не подсвечивается — проверьте путь в Поле и индекс строки.

Проверь себя

  1. Почему проверки в форме недостаточно?

  2. Что указывается в Сообщение.Поле: имя элемента или путь к данным?

  3. Для строки с НомерСтроки = 3 — какой путь в Поле?

Ответы
  1. Запись из кода, обработок и обменов проходит без формы.
  2. Путь к данным (Покупатель, Товары[2].Количество).
  3. Товары[2] — индекс с нуля.
