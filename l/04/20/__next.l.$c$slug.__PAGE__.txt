<div class="callout-title">Коротко</div>
<div class="callout-body"><p>Отбор динамического списка — элемент <code>Список.Отбор.Элементы</code> типа <code>ЭлементОтбораКомпоновкиДанных</code>: <code>ЛевоеЗначение</code> (<code>Новый ПолеКомпоновкиДанных("Покупатель")</code>), <code>ВидСравнения</code>, <code>ПравоеЗначение</code>, <code>Использование</code>. Создаём <strong>свой</strong> элемент один раз и дальше только меняем его значение и <code>Использование</code>. Не вызываем <code>Очистить()</code> — удалим чужие условия.</p></div>
</div>
<p>Продолжаем <code>ФормаСпискаУчебная</code> из темы 19: основной реквизит <code>Список</code>, поле <code>ПокупательОтбор</code> над таблицей. Для проверки нужны накладные минимум двух покупателей.</p>
<h2 id="задача">Задача</h2>
<p>В списке накладных менеджер хочет выбрать покупателя в поле над таблицей — и сразу видеть только его накладные. Пользователь может настроить отбор и сам (<strong>Ещё → Настроить список</strong>), но удобнее одно поле.</p>
<p>Отбор динамического списка устроен так же, как отбор отчёта СКД (<a href="/restart/l/03/24/" data-internal="true">24. Отбор в СКД</a>): это набор <strong>условий</strong>. Каждое условие — элемент отбора с четырьмя частями:</p>
<figure data-rehype-pretty-code-figure=""><pre tabindex="0" data-language="plaintext" data-theme="mono"><code data-language="plaintext" data-theme="mono" style="display: grid;"><span data-line=""><span>[✓]   Покупатель    Равно    Ромашка</span></span>
<span data-line=""><span> │        │           │         │</span></span>
<span data-line=""><span>Использование  ЛевоеЗначение  ВидСравнения  ПравоеЗначение</span></span></code></pre></figure>
<p>Наша задача из кода: создать <strong>одно своё</strong> условие «Покупатель = значение поля» и включать или выключать его, когда меняется поле.</p>
<h2 id="элемент-отбора">Элемент отбора</h2>

























<div class="table-wrap"><table><thead><tr><th>Свойство</th><th>Наш пример</th></tr></thead><tbody><tr><td><code>ЛевоеЗначение</code></td><td><code>Новый ПолеКомпоновкиДанных("Покупатель")</code> — <strong>имя поля списка</strong>, не синоним и не <code>Объект.Покупатель</code></td></tr><tr><td><code>ВидСравнения</code></td><td><code>ВидСравненияКомпоновкиДанных.Равно</code></td></tr><tr><td><code>ПравоеЗначение</code></td><td>Ссылка из <code>ПокупательОтбор</code></td></tr><tr><td><code>Использование</code></td><td><code>Истина</code>, если покупатель выбран</td></tr></tbody></table></div>
<div class="callout callout-warning" data-callout="warning">
<div class="callout-title">Выключено ≠ равно пустому</div>
<div class="callout-body"><p>«Показать всех» — <code>Использование = Ложь</code>. Включённое равенство пустой ссылке покажет только документы <strong>без</strong> покупателя.</p></div>

<span data-line=""><span style="color:var(--shiki-foreground)">		НашОтбор.ЛевоеЗначение </span><span style="color:var(--shiki-token-keyword)">=</span><span style="color:var(--shiki-token-function)"> Новый</span><span style="color:var(--shiki-foreground)"> ПолеКомпоновкиДанных(</span><span style="color:var(--shiki-token-string-expression)">"Покупатель"</span><span style="color:var(--shiki-foreground)">)</span><span style="color:var(--shiki-token-keyword)">;</span></span>
<span data-line=""><span style="color:var(--shiki-foreground)">		НашОтбор.ВидСравнения </span><span style="color:var(--shiki-token-keyword)">=</span><span style="color:var(--shiki-foreground)"> ВидСравненияКомпоновкиДанных.Равно</span><span style="color:var(--shiki-token-keyword)">;</span></span>

<span data-line=""> </span>
<span data-line=""><span style="color:var(--shiki-token-keyword)">КонецПроцедуры</span></span></code></pre></figure>
<p>Разберём процедуру <code>УстановитьОтборПокупателя</code> по шагам:</p>
<ol>
<li><strong>Ищем своё условие.</strong> Перебираем все элементы отбора и ищем тот, у которого <code>Представление</code> = наша метка «Покупатель из поля учебной формы». Метка нужна, чтобы отличить <strong>наше</strong> условие от условий, которые настроил пользователь.</li>
<li><strong>Не нашли — создаём</strong> (<code>Отбор.Элементы.Добавить</code>): задаём метку, поле (<code>ЛевоеЗначение</code>) и вид сравнения «Равно».</li>
<li><strong>Задаём значение</strong> — покупатель из поля (<code>ПравоеЗначение</code>).</li>
<li><strong>Включаем условие, только если покупатель выбран</strong> (<code>Использование</code>). Поле очистили — условие выключается, список показывает всех.</li>
</ol>
<p>Первый вызов создаёт условие, следующие — находят и меняют его. Так не накапливаются «= А», «= Б» одновременно (иначе список станет пустым). Тип элемента проверяем, потому что в коллекции бывают <strong>группы</strong> отбора.</p>
<div class="callout callout-tip" data-callout="tip">
<div class="callout-title">В типовых конфигурациях</div>
<div class="callout-body"><p>Часто встречается <code>ОбщегоНазначенияКлиентСервер.УстановитьЭлементОтбораДинамическогоСписка(...)</code> — это процедура <strong>БСП</strong>, а не платформы. Без БСП она не заработает. Здесь используем объекты платформы. См. <a href="/restart/l/05/09/" data-internal="true">БСП и типовые конфигурации</a>.</p></div>
</div>
<h2 id="фиксированные-и-пользовательские-настройки">Фиксированные и пользовательские настройки</h2>
<p><code>Список.Отбор</code> — <strong>фиксированный</strong> отбор формы. Пользовательские настройки (например, «только проведённые») живут на другом уровне компоновщика и действуют <strong>вместе</strong> с нашим условием. Разница уровней — в <a href="https://its.1c.ru/db/content/updlib/src/bsp2/2.2/updatessl_2.2.htm" target="_blank" rel="noopener noreferrer">пояснениях к БСП</a>.</p>

<h2 id="проверка">Проверка</h2>
<ol>
<li>Поле пустое — ограничения нет.</li>
<li>Покупатель А → только накладные А; Б → только Б (а не пустой список).</li>
<li>Переключаем много раз — число условий не растёт.</li>
<li>Пользовательская настройка «Проведён = Да» + «Все покупатели» → проведённые разных покупателей; снова А → проведённые А.</li>
</ol>
