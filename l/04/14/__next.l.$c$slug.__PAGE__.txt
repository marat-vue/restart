<div class="callout-body"><p><code>Объект</code> в форме — <strong>данные формы</strong>, у них нет экспортных методов модуля объекта. Чтобы вызвать метод объекта для <strong>текущих, ещё не записанных</strong> данных: на сервере <code>РеквизитФормыВЗначение("Объект")</code> → метод → <code>ЗначениеВРеквизитФормы(Объект, "Объект")</code>. <code>Объект.Ссылка.ПолучитьОбъект()</code> прочитает <strong>сохранённую</strong> версию — это другой источник.</p></div>

<h2 id="зачем-нужны-данные-формы">Зачем нужны «данные формы»</h2>
<p>В уроке 13 мы написали в модуле объекта экспортную процедуру <code>ПересчитатьСуммыТоваров()</code>. Логично захотеть вызвать её из формы: <code>Объект.ПересчитатьСуммыТоваров()</code>. Но это ошибка — у <code>Объект</code> такого метода нет. Почему?</p>
<p>Настоящий <strong>объект документа</strong> (<code>ДокументОбъект.РасходнаяНакладная</code>) — тяжёлая вещь: у него есть модуль, методы <code>Записать()</code>, <code>Провести()</code>, доступ к базе. Такой объект живёт <strong>только на сервере</strong>. На компьютер пользователя (тонкий клиент, браузер) его передать нельзя.</p>
<p>Поэтому платформа делает для формы <strong>облегчённую копию</strong> — «данные формы». В ней есть все значения реквизитов и строки таблиц, но нет методов объекта. Аналогия — <strong>фотокопия паспорта</strong>: на ней все данные, по ней удобно сверять и заполнять бланки, но предъявить её на границе вместо паспорта нельзя.</p>
<p>Когда нужен именно метод объекта, на сервере делаем три шага:</p>
<pre><pre class="mermaid-source">flowchart LR
    A["Данные формы&#x3C;br/>(Объект)"] -- "1. РеквизитФормыВЗначение" --> B["Объект документа&#x3C;br/>с методами"]
    B -- "2. вызываем метод" --> B
    B -- "3. ЗначениеВРеквизитФормы" --> A
</pre></pre>
<ol>
<li>Из данных формы получаем настоящий объект документа.</li>
<li>Вызываем у него нужный метод.</li>
<li>Кладём изменённый объект обратно в данные формы — чтобы пользователь увидел результат.</li>
</ol>
<h2 id="какие-значения-бывают">Какие значения бывают</h2>





























<div class="table-wrap"><table><thead><tr><th>Значение</th><th>Что это</th></tr></thead><tbody><tr><td><code>Объект</code> в модуле формы</td><td>Данные формы текущего окна</td></tr><tr><td><code>Объект.Ссылка</code></td><td>Ссылка на документ в базе (у нового — пустая)</td></tr><tr><td><code>Документы.РасходнаяНакладная.СоздатьДокумент()</code></td><td>Новый прикладной объект (сервер)</td></tr><tr><td><code>Ссылка.ПолучитьОбъект()</code></td><td>Объект, прочитанный <strong>из базы</strong> (сервер)</td></tr><tr><td><code>РеквизитФормыВЗначение("Объект")</code></td><td>Объект из <strong>текущих данных формы</strong> (сервер, <code>&#x26;НаСервере</code>)</td></tr></tbody></table></div>
<p>Данные формы нужны, чтобы документ можно было редактировать в тонком и веб-клиенте, где прикладного объекта нет. При стандартной записи их преобразует платформа, в своём алгоритме — мы явно. См. <a href="https://kb.1ci.com/1C_Enterprise_Platform/Tutorials/Practical_developer_guide_8.3/Lesson_27._Form_development_techniques/Form_data_types/" target="_blank" rel="noopener noreferrer">пособие 1С о типах данных формы</a>.</p>

<div class="callout-title">Не гоняем объект на сервер без нужды</div>
<div class="callout-body"><p>Пересчёт одной строки при вводе остаётся на клиенте (тема 10). Преобразование нужно, когда действительно требуется метод объекта или серверный алгоритм.</p></div>

<h2 id="почему-не-читаем-по-ссылке">Почему не читаем по ссылке</h2>
<p>Накладная записана с количеством <strong>2</strong>, пользователь изменил на <strong>5</strong> и не записал:</p>

















<div class="table-wrap"><table><thead><tr><th>Способ</th><th>Что получим</th></tr></thead><tbody><tr><td><code>Объект.Ссылка.ПолучитьОбъект()</code></td><td>2 — сохранённая версия</td></tr><tr><td><code>РеквизитФормыВЗначение("Объект")</code></td><td>5 — текущие данные окна</td></tr></tbody></table></div>
<p>Для обработки редактируемого документа — данные формы. У нового документа ссылки нет вовсе. Не заменяем <code>Объект</code> данными произвольно прочитанного документа — потеряем несохранённые изменения.</p>
<h2 id="где-запись">Где запись</h2>
<p>В примере нет <code>НакладнаяОбъект.Записать()</code>: команда меняет данные формы, а записывает пользователь стандартной командой (порядок событий — тема 13). Ручная запись преобразованного объекта — другой сценарий, где разработчик сам отвечает за синхронизацию формы, блокировки и ошибки.</p>
<h2 id="проверка">Проверка</h2>
<ol>
<li>Новая накладная: количество 2, цена 150 → «Пересчитать на сервере» → сумма и итог <strong>300</strong>.</li>
<li>Количество 4, не записывая → команда → расчёт по <strong>4</strong>, а не по данным базы.</li>
<li>Записываем, переоткрываем — итог соответствует строкам.</li>
</ol>
