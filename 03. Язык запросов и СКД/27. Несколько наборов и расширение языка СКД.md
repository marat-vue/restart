> [!abstract] Коротко
> Наборы данных: **Запрос**, **Объект** (готовая таблица значений из кода), **Объединение**. Наборы с разной детализацией связывают на вкладке «Связи наборов данных». Фигурные скобки `{ВЫБРАТЬ …}` — расширение языка запросов для СКД; обычный `Запрос` их не выполняет.

## Когда одного запроса мало

В большинстве отчётов хватает одного набора данных — запроса. Но иногда данные приходят из разных мест или имеют разную детализацию. Для этого в СКД есть три вида наборов.

| Набор | Откуда данные | Пример задачи |
| --- | --- | --- |
| **Запрос** | Запрос к базе | Обычный отчёт по регистру — 90% случаев |
| **Объект** | Готовая коллекция из кода, например таблица значений | Данные из файла, из внешнего сервиса или посчитанные сложным алгоритмом |
| **Объединение** | Несколько дочерних наборов, сложенные друг под другом | Продажи из регистра + план продаж из другой таблицы |

![[27-Виды-наборов-данных.png]]

*Кнопка добавления на вкладке «Наборы данных»: три вида наборов — запрос, объект, объединение.*

Набор «Объединение» работает как `ОБЪЕДИНИТЬ ВСЕ` в запросах ([[13. Объединение результатов]]), только собирается мышкой: создаём набор-объединение и добавляем в него дочерние наборы с одинаковыми именами полей.

## Связи наборов: данные разной детализации

Типичная ловушка: нужны и итоги накладных (из шапок), и строки товаров. Если сделать одним запросом с соединением, итог шапки повторится в каждой строке товаров и при суммировании задвоится ([[07. Запрос к табличной части документа]]).

СКД позволяет держать их в **двух отдельных наборах** и связать:

| Набор | Одна строка — это | Поля |
| --- | --- | --- |
| `Документы` | Одна накладная | `Накладная`, `Покупатель`, `ИтоговаяСумма` |
| `Строки` | Одна строка товаров | `Накладная`, `Товар`, `Количество`, `Сумма` |

Связываем на вкладке **Связи наборов данных**:

1. **Добавить** связь.
2. **Источник связи** — `Документы`, **Приёмник связи** — `Строки`.
3. **Выражение источника** — `Накладная`, **Выражение приёмника** — `Накладная`.

Это работает как левое соединение: все строки источника + подходящие строки приёмника. Но, в отличие от соединения в одном запросе, СКД считает ресурсы каждого набора по **его собственным** строкам: `ИтоговаяСумма` суммируется по документам, а не по строкам товаров. Обязательно сверьте итог на тестовых данных.

> [!warning] Детализацию всё равно продумываем
> Несколько наборов не отменяют главный вопрос: «на каком уровне считается каждый показатель?». Итог шапки — по документам, сумма строк — по товарам. Не переносите итог шапки в каждую строку товаров «для удобства» — получите удвоение.

## Фигурные скобки в запросе СКД

Открыв набор данных типового отчёта, вы можете увидеть странные конструкции:

```1C
ВЫБРАТЬ
    П.Номенклатура,
    П.СуммаОборот
{ВЫБРАТЬ
    Номенклатура.*,
    СуммаОборот}
ИЗ
    РегистрНакопления.Продажи.Обороты(
        {(&НачалоПериода)}, {(&КонецПериода)}, , ) КАК П
{ГДЕ
    П.Номенклатура.*}
```

Части в **фигурных скобках** — это **расширение языка запросов для СКД**. Они не выполняются как обычный запрос, а сообщают СКД дополнительную информацию:

| Конструкция | Смысл |
| --- | --- |
| `{ВЫБРАТЬ …}` | Какие поля пользователь может выбрать в настройках. `Номенклатура.*` — само поле и все его реквизиты через точку |
| `{ГДЕ …}` | По каким полям разрешены отборы, которые СКД перенесёт прямо в запрос |
| `{(&Параметр)}` | Параметр необязательный: если пользователь его не задал, СКД уберёт его из запроса |

Новичку писать эти конструкции не нужно: при включённом **Автозаполнении** СКД сама определяет доступные поля и отборы. Достаточно уметь их **узнавать**, когда встречаете в чужих отчётах.

> [!warning] Не копируйте в `Запрос` как есть
> Объект `Запрос` встроенного языка не понимает фигурных скобок СКД — запрос с ними завершится ошибкой. Если нужно перенести текст из СКД в код, конструкции в `{…}` надо осознанно убрать или переписать (например, `{(&НачалоПериода)}` → `&НачалоПериода`).

## Проверка

1. Откройте схему существующего отчёта `ОтчетПоПродажам` и посмотрите вкладку **Связи наборов данных** — в простом отчёте она пустая.
2. Сравните: отчёт «шапки + строки» одним запросом с соединением и двумя связанными наборами. Во втором случае общий итог `ИтоговаяСумма` не задваивается.

> [!question]- Проверь себя
> 1. Когда нужен набор «Объект»?
> 2. Можно ли скопировать текст с `{…}` в объект `Запрос` как есть?
> 3. Почему не стоит переносить итог шапки в каждую строку товаров?
>
> > [!success]- Ответы
> > 1. Когда данные подготовлены кодом (например, таблица значений) и передаются в СКД.
> > 2. Нет, это расширение СКД.
> > 3. При суммировании итог умножится на число строк.
