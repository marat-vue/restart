> [!abstract] Коротко
> В запросе можно вычислять поля (`Т.Количество * Т.Цена`), использовать `ВЫБОР КОГДА … ТОГДА … ИНАЧЕ … КОНЕЦ`, функции дат (`НАЧАЛОПЕРИОДА`, `КОНЕЦПЕРИОДА`, `ДОБАВИТЬКДАТЕ`), строк (`ПОДСТРОКА`) и приведения (`ВЫРАЗИТЬ`). Функции языка запросов, встроенного языка и выражений СКД — **разные наборы**.

## Вычисляемая колонка

В `ВЫБРАТЬ` можно писать не только поля, но и **выражения** — формулы над полями. Каждая строка результата получит своё вычисленное значение, как формула в ячейке Excel, протянутая вниз.

```1C
ВЫБРАТЬ
    Т.Товар КАК Товар,
    Т.Количество КАК Количество,
    Т.Цена КАК Цена,
    Т.Количество * Т.Цена КАК РасчётнаяСумма
ИЗ
    Документ.РасходнаяНакладная.Товары КАК Т
```

| Товар | Количество | Цена | РасчётнаяСумма |
| --- | --- | --- | --- |
| Чайник | 2 | 150 | 300 |
| Кружка | 3 | 50 | 150 |

Доступны обычные арифметические операции: `+ - * /`. Псевдоним (`КАК РасчётнаяСумма`) для выражения обязателен по смыслу: иначе колонка получит безликое имя вроде `Поле1`.

Вычисление происходит **только в результате запроса**. Записанное поле `Т.Сумма` в базе не меняется — запрос ничего не изменяет.

## Условие внутри колонки: `ВЫБОР`

Иногда значение колонки зависит от условия. Для этого есть конструкция `ВЫБОР` — аналог `Если` встроенного языка и тернарного `?()`:

```1C
ВЫБОР
    КОГДА Т.Количество = 0 ТОГДА 0
    ИНАЧЕ Т.Сумма / Т.Количество
КОНЕЦ КАК СредняяЦенаСтроки
```

Читаем: «**когда** количество равно нулю — **тогда** 0, **иначе** сумма, делённая на количество».

| Часть | Смысл |
| --- | --- |
| `ВЫБОР … КОНЕЦ` | Начало и конец конструкции |
| `КОГДА условие ТОГДА значение` | Ветка; их может быть несколько |
| `ИНАЧЕ значение` | Если ни одно условие не подошло (если не указать — будет `NULL`) |

Условия проверяются **сверху вниз**, срабатывает первое истинное. Пример с несколькими ветками — категория продажи:

```1C
ВЫБОР
    КОГДА Т.Сумма >= 10000 ТОГДА "Крупная"
    КОГДА Т.Сумма >= 1000 ТОГДА "Средняя"
    ИНАЧЕ "Мелкая"
КОНЕЦ КАК Категория
```

Строка на 15000 ₽ получит «Крупная» — до второй ветки дело не дойдёт.

> [!warning] Деление на ноль
> Если в какой-то строке количество равно 0, выражение `Т.Сумма / Т.Количество` вызовет ошибку деления на ноль, и весь запрос не выполнится. Поэтому деление почти всегда оборачиваем в `ВЫБОР`, как в примере выше.

## Функции языка запросов

| Выражение | Что получим | Пример для даты 15.10.2026 14:30 |
| --- | --- | --- |
| `НАЧАЛОПЕРИОДА(Н.Дата, МЕСЯЦ)` | Начало месяца | 01.10.2026 00:00:00 |
| `КОНЕЦПЕРИОДА(Н.Дата, ДЕНЬ)` | Конец дня | 15.10.2026 23:59:59 |
| `ГОД(Н.Дата)`, `МЕСЯЦ(Н.Дата)`, `ДЕНЬ(Н.Дата)` | Часть даты числом | 2026, 10, 15 |
| `ДОБАВИТЬКДАТЕ(Н.Дата, ДЕНЬ, 1)` | Дата со сдвигом | 16.10.2026 14:30 |
| `РАЗНОСТЬДАТ(Н.Дата, &Сегодня, ДЕНЬ)` | Разница между датами в днях | Сколько дней прошло |
| `ПОДСТРОКА(Н.Наименование, 1, 3)` | Часть строки: с 1-го символа, 3 символа | «Чай» из «Чайник» |
| `ВРЕГ(Н.Наименование)` | Строка в верхнем регистре | «ЧАЙНИК» |
| `ПРЕДСТАВЛЕНИЕ(Н.Покупатель)` | Текст для показа ссылки | «ООО Ромашка» |
| `ВЫРАЗИТЬ(Т.Сумма КАК ЧИСЛО(15, 2))` | Значение, приведённое к типу | Число с 2 знаками |

Периоды в функциях дат — ключевые слова без кавычек: `СЕКУНДА`, `МИНУТА`, `ЧАС`, `ДЕНЬ`, `НЕДЕЛЯ`, `МЕСЯЦ`, `КВАРТАЛ`, `ГОД`.

Типичное применение — группировка по месяцам:

```1C
ВЫБРАТЬ
    НАЧАЛОПЕРИОДА(Н.Дата, МЕСЯЦ) КАК Месяц,
    СУММА(Н.ИтоговаяСумма) КАК Выручка
ИЗ Документ.РасходнаяНакладная КАК Н
ГДЕ Н.Проведен
СГРУППИРОВАТЬ ПО НАЧАЛОПЕРИОДА(Н.Дата, МЕСЯЦ)
```

Все октябрьские накладные получат одинаковое значение «01.10.2026» и сложатся в одну строку.

## Три похожих, но разных языка

В 1С функции с похожими названиями есть в трёх местах, и они **не взаимозаменяемы**:

| Где | Конец дня | Как пишется период |
| --- | --- | --- |
| Встроенный язык (код модуля) | `КонецДня(Дата)` | Отдельная функция для каждого периода |
| Язык запросов (текст запроса) | `КОНЕЦПЕРИОДА(Дата, ДЕНЬ)` | Ключевое слово без кавычек |
| Выражения СКД (настройки отчёта) | `КонецПериода(&Дата, "День")` | Строка в кавычках |

Написать в тексте запроса `КонецДня(Н.Дата)` нельзя — такой функции в языке запросов нет. Либо используем `КОНЕЦПЕРИОДА` в запросе, либо считаем значение в коде и передаём параметром.

## Значения прямо в тексте

| Что | Как записать в запросе |
| --- | --- |
| Число | `1000`, `12.5` (точка) |
| Строка | `"Продажа"` |
| Булево | `ИСТИНА`, `ЛОЖЬ` |
| Отсутствие значения | `NULL` |
| Дата | `ДАТАВРЕМЯ(2026, 10, 1)` |
| Значение из конфигурации | `ЗНАЧЕНИЕ(Перечисление.ВидыНоменклатуры.Товар)` |

Даты и другие меняющиеся значения лучше передавать **параметрами** — так запрос не придётся переписывать.

> [!warning] Кавычки внутри `Запрос.Текст`
> Текст запроса во встроенном языке сам находится внутри кавычек. Поэтому кавычки строк *внутри* запроса удваиваем:
> ```1C
> Запрос.Текст = "ВЫБРАТЬ ""Продажа"" КАК Вид ИЗ Документ.РасходнаяНакладная КАК Н";
> ```
> В самом запросе получится `"Продажа"`. Конструктор запроса удваивает кавычки сам.

## Проверка

1. Выведите дату документов и `НАЧАЛОПЕРИОДА(Н.Дата, МЕСЯЦ)` — все октябрьские получат 01.10.2026 00:00:00.
2. Добавьте колонку с `ВЫБОР` и категорией продажи — проверьте накладную ровно на 1000 ₽: она должна попасть в «Средняя».
3. Создайте строку товара с количеством 0 и выведите `Т.Сумма / Т.Количество` без `ВЫБОР` — увидите ошибку деления на ноль.

> [!question]- Проверь себя
> 1. Как защититься от деления на ноль в запросе?
> 2. Можно ли в запросе вызвать `КонецДня()` встроенного языка?
> 3. Как записать строку «Продажа» внутри `Запрос.Текст`?
>
> > [!success]- Ответы
> > 1. `ВЫБОР КОГДА Количество = 0 ТОГДА 0 ИНАЧЕ Сумма / Количество КОНЕЦ`.
> > 2. Нет; в запросе — `КОНЕЦПЕРИОДА(Дата, ДЕНЬ)`, либо считаем границу в коде и передаём параметром.
> > 3. `""Продажа""` — удвоенные кавычки.
