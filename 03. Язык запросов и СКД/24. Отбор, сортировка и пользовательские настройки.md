> [!abstract] Коротко
> **Отбор** СКД — условие компоновки (может перейти в запрос), **параметр** — значение для запроса/выражения. Сортировку групп задают на уровне группировки. Элементы, которые пользователь может менять, включают в **пользовательские настройки**. Отбор отчёта не заменяет права доступа.

## Отбор: показать только часть данных

Отчёт за октябрь показывает продажи всем покупателям. Менеджер хочет видеть только «Ромашку». Переписывать запрос не нужно: в СКД есть **отбор** — условие, которое можно включать и выключать в настройках, в том числе самому пользователю.

## Шаг 1. Добавляем отбор по покупателю

1. На вкладке **Настройки** выделяем корень **Отчёт** (отбор будет действовать на весь отчёт).
2. Внизу открываем закладку **Отбор**. Слева — доступные поля, справа — условия.
3. Двойным щелчком переносим `Контрагент` вправо.
4. **Вид сравнения** — `Равно`.
5. **Значение** — выбираем контрагента кнопкой выбора из справочника. Не вводим название текстом: отбор сравнивает **ссылки**.
6. Флажок слева от строки — **использование** условия. Включён — отбор работает, выключен — условие «спит».

Виды сравнения, которые пригодятся:

| Вид сравнения | Смысл | Пример |
| --- | --- | --- |
| Равно / Не равно | Одно значение | Покупатель = Ромашка |
| В списке / Не в списке | Несколько значений | Покупатель в списке (Ромашка, Петров) |
| В группе | Элемент группы иерархического справочника | Товар в группе «Чайники» |
| Заполнено / Не заполнено | Есть ли значение | Покупатель не заполнен |
| Больше / Меньше | Для чисел и дат | Выручка больше 1000 |
| Содержит | Часть строки | Наименование содержит «чай» |

### Несколько условий

Условия в списке по умолчанию соединяются через **И**. Чтобы получить «Ромашка **или** Петров», создаём **группу ИЛИ**: кнопка **Сгруппировать условия** → тип группы «Группа ИЛИ» → переносим в неё оба условия. Хотя для этого случая проще вид сравнения «В списке».

> [!warning] «Выключено» ≠ «равно пустому»
> Если пользователю не нужен отбор, условие должно быть **выключено** (флажок снят). Включённое условие «Контрагент = *пусто*» — это не «без отбора», а поиск продаж **с незаполненным** покупателем. Скорее всего, отчёт будет пустым.

## Шаг 2. Даём пользователю менять отбор

По умолчанию отбор задаёт разработчик, а пользователь его не видит. Чтобы покупателя можно было выбрать на форме отчёта:

1. Выделяем строку условия → **ПКМ → Свойства элемента пользовательских настроек**.
2. Включаем **Включать в пользовательские настройки**.
3. Режим — **Быстрый доступ** (поле в шапке отчёта) или **Обычный** (в окне «Настройки…»).
4. Само условие оставляем **выключенным**: пользователь включит его, когда понадобится.

## Сортировка

Задача: товары с наибольшей выручкой — сверху.

1. Выделяем в дереве **группировку `Номенклатура`** — не корень! Сортируем именно строки товаров.
2. Внизу закладка **Сортировка** → переносим `Выручка` → направление **По убыванию**.

| Выделен узел | Что отсортируется |
| --- | --- |
| Группировка `Номенклатура` | Порядок **товаров** по их итоговой выручке |
| `<Детальные записи>` | Порядок строк **внутри** каждого товара |
| Корень «Отчёт» | Общий порядок для узлов, у которых своя сортировка не задана |

После формирования проверяем порядок именно **групп** товаров, а не только строк покупателей.

## Отбор и параметр — в чём разница

| | Параметр ([[22. Параметры периода в СКД]]) | Отбор |
| --- | --- | --- |
| Что это | Значение, которое передаётся **в запрос** или формулу (`&НачалоПериода`) | Условие на **поля** отчёта |
| Где виден в схеме | Вкладка «Параметры» | Закладка «Отбор» в настройках |
| Пример | Период отчёта | Только покупатель Ромашка |
| Можно выключить | Нет — запрос без значения не выполнится | Да — флажком |

СКД умеет сама переносить отбор в запрос: условие «Контрагент = Ромашка» станет частью `ГДЕ` или параметров виртуальной таблицы. Поэтому отбор не означает, что СКД сначала читает все данные, а потом фильтрует.

> [!warning] Отбор отчёта — не защита данных
> Если менеджеру **нельзя** видеть чужих покупателей, отбор в отчёте не поможет: он его просто выключит. Ограничивать доступ нужно правами (RLS) — [[01. Основы конфигурирования/19. Пользователи и Роли|19. Пользователи и Роли]].

## Что видит пользователь

В режиме 1С:Предприятия у формы отчёта:
- в шапке — элементы **быстрого доступа** (период, покупатель);
- кнопка **Настройки…** — элементы «обычного» режима;
- **Ещё → Изменить вариант…** — полный редактор настроек, похожий на вкладку «Настройки» Конфигуратора (если позволяют права).

![[17-Пользовательские-настройки.jpg]]

*Пользовательские настройки существующего отчёта: доступны только начало и конец периода. После включения отбора в пользовательские настройки он появится здесь.*

![[19-Отбор-в-варианте.jpg]]

*Полный редактор варианта в режиме пользователя: здесь можно добавлять доступные условия отбора.*

## Проверка

1. Сформируйте отчёт без отбора — запишите общий итог.
2. Включите отбор «Контрагент = Ромашка» — остались только её продажи; итог уменьшился и не превышает общего.
3. Включите отбор с пустым значением — отчёт пустой (или только продажи без покупателя). Выключите отбор.
4. Задайте сортировку по выручке на группировке — товары выстроились по убыванию итогов.

> [!question]- Проверь себя
> 1. Включённое условие «Контрагент = пустая ссылка» — это «без отбора»?
> 2. Где задать сортировку товаров по выручке?
> 3. Чем отбор отличается от параметра?
>
> > [!success]- Ответы
> > 1. Нет, это поиск продаж с пустым контрагентом. Для «без отбора» условие выключают.
> > 2. На вкладке «Сортировка» у группировки `Номенклатура`.
> > 3. Параметр передаёт значение в запрос; отбор — условие компоновки, которое СКД применяет сама.
