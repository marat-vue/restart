> [!abstract] Коротко
> `ПОМЕСТИТЬ ВТ_Имя` сохраняет результат во **временную таблицу**, `;` разделяет запросы **пакета**, следующие части видят ВТ предыдущих. `Выполнить()` возвращает результат последнего запроса, `ВыполнитьПакет()` — массив результатов. Между разными объектами `Запрос` ВТ передаются через `МенеджерВременныхТаблиц`.

## Сложный расчёт — по шагам

Вложенный запрос из прошлого урока — это «черновик» прямо внутри основного запроса. Когда шагов становится больше или промежуточный результат нужен несколько раз, удобнее разложить расчёт на **отдельные запросы**, которые выполняются один за другим:

1. Первый запрос считает промежуточный результат и **кладёт его во временную таблицу**.
2. Второй запрос берёт данные из этой временной таблицы, как из обычной.
3. И так далее.

Такой набор запросов, выполняемых одним вызовом, называется **пакетом запросов**.

Аналогия: кулинарный рецепт. «Шаг 1: нарежьте овощи и отложите в миску. Шаг 2: обжарьте мясо. Шаг 3: смешайте содержимое миски с мясом». Миска — это временная таблица.

## Пример пакета

```1C
// Шаг 1: выручка по товарам → временная таблица ВТПродажи
ВЫБРАТЬ
    П.Номенклатура КАК Номенклатура,
    СУММА(П.СуммаОборот) КАК Выручка
ПОМЕСТИТЬ ВТПродажи
ИЗ
    РегистрНакопления.Продажи.Обороты(&Начало, &Конец, , ) КАК П
СГРУППИРОВАТЬ ПО
    П.Номенклатура
ИНДЕКСИРОВАТЬ ПО
    Номенклатура
;

// Шаг 2: оставляем крупные продажи
ВЫБРАТЬ
    ВТ.Номенклатура,
    ВТ.Выручка
ИЗ
    ВТПродажи КАК ВТ
ГДЕ
    ВТ.Выручка > &МинимальнаяВыручка
```

> [!info] Комментарии в тексте запроса
> Строки `// Шаг 1` — комментарии; язык запросов их допускает так же, как встроенный язык.

Разберём новые слова:

| Запись | Смысл |
| --- | --- |
| `ПОМЕСТИТЬ ВТПродажи` | Не возвращать результат, а **сохранить** его во временную таблицу с именем `ВТПродажи`. Пишется сразу после списка полей |
| `;` | Разделитель запросов пакета: здесь заканчивается первый запрос и начинается второй |
| `ИЗ ВТПродажи КАК ВТ` | Второй запрос читает временную таблицу, как обычную |
| `ИНДЕКСИРОВАТЬ ПО Номенклатура` | Построить индекс по полю — ускоряет поиск и соединение по нему на больших данных |

Имена временных таблиц принято начинать с `ВТ` — так их сразу видно в тексте.

## Что такое временная таблица

- Она существует **только во время выполнения** пакета (или пока жив менеджер временных таблиц — ниже). После этого исчезает.
- Это **не** объект конфигурации: в дереве Конфигуратора её нет, в базе она не сохраняется.
- Её видят только **следующие** запросы этого пакета. Первый запрос не может читать таблицу, которую создаёт третий.

## Запуск пакета из кода

Весь пакет — вместе с `;` — кладём в `Запрос.Текст` целиком, как один текст:

```1C
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ … ПОМЕСТИТЬ ВТПродажи … ;
|ВЫБРАТЬ … ИЗ ВТПродажи КАК ВТ …";
Запрос.УстановитьПараметр("Начало", НачалоПериода);
Запрос.УстановитьПараметр("Конец", КонецДня(КонецПериода));
Запрос.УстановитьПараметр("МинимальнаяВыручка", 400);

Результат = Запрос.Выполнить();   // результат ПОСЛЕДНЕГО запроса пакета
```

| Метод | Что возвращает |
| --- | --- |
| `Выполнить()` | Результат **последнего** запроса пакета |
| `ВыполнитьПакет()` | **Массив** результатов всех запросов, по порядку. У запросов с `ПОМЕСТИТЬ` результат служебный (число строк во временной таблице) |

```1C
Результаты = Запрос.ВыполнитьПакет();
ТаблицаИтог = Результаты[1].Выгрузить();   // результат второго запроса (индексы с 0)
```

## Пакет в конструкторе

1. Собираем первый запрос как обычно.
2. На вкладке **Дополнительно** выбираем тип запроса **Создание временной таблицы** и задаём имя `ВТПродажи`.
3. Открываем вкладку **Пакет запросов** и кнопкой **Добавить** создаём второй запрос.
4. Во втором запросе в левом списке появится ветка **Временные таблицы** — выбираем из неё `ВТПродажи`.
5. Переключаться между запросами пакета удобно вертикальными закладками у правого края конструктора.

## Нужен ли индекс?

`ИНДЕКСИРОВАТЬ ПО` полезен, когда по полю временной таблицы потом **соединяют** или **отбирают**, и строк много (тысячи и больше). На маленькой таблице построение индекса может занять больше времени, чем сэкономит. В нашем примере второй запрос только фильтрует по выручке, поэтому индекс по номенклатуре подготовлен «на будущее» — для соединения со справочником.

## Временные таблицы между разными запросами

Обычно хватает одного пакета. Но иногда временную таблицу создаёт один объект `Запрос`, а читает другой (например, в разных процедурах). Тогда их связывают общим **менеджером временных таблиц**:

```1C
МенеджерВТ = Новый МенеджерВременныхТаблиц;

Первый = Новый Запрос;
Первый.МенеджерВременныхТаблиц = МенеджерВТ;
Первый.Текст = "ВЫБРАТЬ … ПОМЕСТИТЬ ВТПродажи …";
Первый.Выполнить();                    // ВТПродажи создана и живёт в МенеджерВТ

Второй = Новый Запрос;
Второй.МенеджерВременныхТаблиц = МенеджерВТ;
Второй.Текст = "ВЫБРАТЬ … ИЗ ВТПродажи КАК ВТ";
Результат = Второй.Выполнить();        // читает таблицу, созданную первым запросом

МенеджерВТ.Закрыть();                  // освобождаем временные таблицы
```

Временные таблицы живут, пока существует менеджер. Метод `Закрыть()` удаляет их явно.

## Проверка

1. Выполните пакет через `Выполнить()` — получите только крупные продажи (результат второго запроса).
2. Выполните через `ВыполнитьПакет()` и посмотрите в отладчике размер массива — 2 элемента.
3. Попробуйте в первом запросе прочитать `ВТПродажи` — получите ошибку: таблица ещё не создана.

> [!question]- Проверь себя
> 1. Что вернёт `Запрос.Выполнить()` для пакета из трёх запросов?
> 2. Является ли временная таблица объектом конфигурации?
> 3. Когда нужен `ИНДЕКСИРОВАТЬ ПО`?
>
> > [!success]- Ответы
> > 1. Результат последнего.
> > 2. Нет, она существует только во время работы запроса/менеджера ВТ.
> > 3. Когда по полю ВТ дальше выполняется соединение или отбор на больших данных.
