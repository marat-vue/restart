> [!abstract] Коротко
> Сначала проверяем **смысл**: что означает строка источника, сверяем результат на 2–3 известных записях, после каждого соединения смотрим число строк и суммы. Потом скорость: только нужные поля, отборы в параметрах виртуальных таблиц, никаких запросов в цикле, свёртка перед соединением. `РАЗРЕШЕННЫЕ` не даёт прав — лишь отбрасывает недоступные записи.

## Сначала правильно, потом быстро

Запрос, который быстро возвращает **неверные** числа, хуже медленного. Поэтому порядок всегда такой: сначала убеждаемся, что результат правильный, и только потом думаем о скорости.

## Как проверить смысл запроса

Пять шагов, которые ловят почти все ошибки этого раздела:

1. **Что такое одна строка источника?** Документ, строка товаров, движение регистра, оборот за период? Пока нет ответа — дальше не идём.
2. **Проверьте на 2–3 известных записях.** Создайте в учебной базе документы, результат которых вы можете посчитать в уме, и сравните с запросом.
3. **Собирайте запрос по частям.** Источник → отбор → соединение → группировка. После каждого шага запускайте и смотрите результат.
4. **После каждого соединения сравните число строк и сумму.** Строк или сумма стало больше, чем ожидали? Скорее всего, строки размножились ([[08. Соединения таблиц]]).
5. **Проверьте пограничные случаи.** Пустые данные, последний день периода, одинаковые названия, нулевое количество.

### Пример поиска ошибки

Запрос «выручка по покупателям за октябрь» показывает у Ромашки 1200, а в накладных — 600. Ищем по шагам:

| Шаг | Проверяем | Находим |
| --- | --- | --- |
| Источник | Что за таблица | `Документ.РасходнаяНакладная.Товары` — строки товаров |
| Поле суммы | Откуда сумма | `Т.Ссылка.ИтоговаяСумма` — итог **шапки** |
| Вывод | — | Итог шапки повторяется в каждой строке товара: 2 строки × 600 = 1200 ([[07. Запрос к табличной части документа]]) |

Исправление: суммировать `Т.Сумма` или брать итог из таблицы шапок.

## Как ускорить запрос

| Правило | Почему помогает |
| --- | --- |
| Выбирайте только нужные поля, не `ВЫБРАТЬ *` | Меньше данных читается и передаётся; текст понятнее |
| Отборы по измерениям — в параметры виртуальных таблиц | Платформа считает только нужное ([[16. Виртуальные таблицы регистров накопления]]) |
| Не выполняйте запрос в цикле | Одно обращение к базе вместо сотен (пример ниже) |
| Избегайте длинных цепочек через точку | Каждая точка — скрытое соединение |
| Сворачивайте таблицы до нужных разрезов перед соединением | Меньше строк участвует в соединении |
| Не оборачивайте поле в функцию в условии | `ГДЕ НАЧАЛОПЕРИОДА(Н.Дата, МЕСЯЦ) = &Месяц` медленнее, чем `ГДЕ Н.Дата >= &Начало И Н.Дата < &Конец`: во втором случае база может использовать индекс по дате |

### Главная ошибка: запрос в цикле

Задача: для каждой строки накладной узнать цену товара. **Плохо:**

```1C
Для Каждого СтрокаТовара Из Товары Цикл
    Запрос = Новый Запрос("ВЫБРАТЬ Ц.Цена ИЗ РегистрСведений.ЦеныНоменклатуры.СрезПоследних(&Дата, Номенклатура = &Товар) КАК Ц");
    Запрос.УстановитьПараметр("Дата", Дата);
    Запрос.УстановитьПараметр("Товар", СтрокаТовара.Товар);
    // ... 100 строк = 100 обращений к базе
КонецЦикла;
```

Каждый запрос — отдельный «поход» в базу. При 100 строках — 100 походов, при 1000 — тысяча.

**Хорошо:** собрать все товары в массив и получить все цены **одним** запросом:

```1C
ТоварыДокумента = Товары.ВыгрузитьКолонку("Товар");

Запрос = Новый Запрос(
"ВЫБРАТЬ Ц.Номенклатура, Ц.Цена
|ИЗ РегистрСведений.ЦеныНоменклатуры.СрезПоследних(&Дата, Номенклатура В (&Товары)) КАК Ц");
Запрос.УстановитьПараметр("Дата", Дата);
Запрос.УстановитьПараметр("Товары", ТоварыДокумента);
Цены = Запрос.Выполнить().Выгрузить();   // одна таблица со всеми ценами

Для Каждого СтрокаТовара Из Товары Цикл
    НайденнаяЦена = Цены.Найти(СтрокаТовара.Товар, "Номенклатура");
    Если НайденнаяЦена <> Неопределено Тогда
        СтрокаТовара.Цена = НайденнаяЦена.Цена;
    КонецЕсли;
КонецЦикла;
```

Цикл остался, но он работает с таблицей в памяти, а не с базой. На собеседовании про «запросы в цикле» спрашивают почти всегда.

> [!info] Измеряйте, а не угадывайте
> Временные таблицы, индексы, перестановка соединений иногда ускоряют запрос, а иногда нет. Более длинный текст может работать быстрее короткого. Решение принимают по замерам (например, инструментом «Замер производительности» в меню «Отладка»), а не на глаз.

## Права доступа и «пропавшие» данные

Запрос выполняется **с правами текущего пользователя**. Если у администратора данные есть, а у пользователя — нет, причина обычно в правах:

- у роли пользователя нет права «Чтение» на таблицу — запрос завершится ошибкой «Недостаточно прав»;
- настроено ограничение на уровне записей (RLS) — пользователь видит только часть строк.

`ВЫБРАТЬ РАЗРЕШЕННЫЕ` указывает платформе: «молча пропусти строки, которые пользователю недоступны, вместо ошибки». Это **не даёт новых прав** — только отбрасывает недоступное. Поэтому для общего итога по всей организации такой результат может оказаться неполным. Подробно о правах — [[05. Профессиональная разработка/05. Права доступа и RLS в коде|05. Права доступа и RLS в коде]].

## Как отладить запрос

1. В серверной процедуре учебной обработки ставим точку останова (`F9`) на строке **после** `Запрос.Выполнить()`.
2. Запускаем в режиме отладки и нажимаем кнопку.
3. Когда отладчик остановится, выделяем переменную результата и открываем **Вычислить выражение** (`Shift+F9`). Вводим `Результат.Выгрузить()` — увидим таблицу со всеми колонками и строками.
4. Там же можно проверить параметры: `Запрос.Параметры`.

Ошибка «Поле не найдено» обычно означает опечатку в имени поля, неверный псевдоним или то, что такого реквизита нет в **вашей** конфигурации.

Синтаксис операторов можно уточнить в справке: **Справка → Содержание справки → Встроенный язык → Работа с запросами** (названия разделов немного отличаются по версиям).

## Проверка

1. Найдите в своём коде (или придумайте) пример запроса в цикле и перепишите его на один запрос с массивом.
2. Создайте пользователя без роли с правом чтения регистра продаж и выполните запрос под ним — получите ошибку прав.

> [!question]- Проверь себя
> 1. Почему запрос в цикле по строкам документа — плохо?
> 2. У администратора данные есть, у пользователя — нет. Что проверить?
> 3. Ускоряет ли `ВЫБРАТЬ *`?
>
> > [!success]- Ответы
> > 1. Сотни обращений к базе вместо одного; данные нужно получить одним запросом.
> > 2. Роли и ограничения доступа к данным (RLS).
> > 3. Нет: читаются лишние поля, текст хуже сопровождать.
