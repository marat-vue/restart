> [!abstract] Коротко
> В `ПриКомпоновкеРезультата` модуля отчёта можно вывести отчёт кодом: `КомпоновщикМакетаКомпоновкиДанных.Выполнить(Схема, Настройки)` → `ПроцессорКомпоновкиДанных.Инициализировать(Макет)` → `ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент.Вывести(Процессор)`. `СтандартнаяОбработка = Ложь` отключает автоматический вывод.

## Когда отчёт формируют кодом

Отчёт, который мы собрали, работает **без единой строки кода**: пользователь жмёт «Сформировать», платформа сама берёт схему и настройки и выводит результат. Код понадобится, если нужно:
- подготовить данные, которых нет в базе, и передать их в набор «Объект»;
- изменить настройки перед выводом (например, принудительно задать отбор);
- вывести результат не на экран, а в файл или в другую форму;
- сформировать отчёт из обработки или регламентного задания.

Для junior-разработчика важно **понимать** этот механизм: он встречается в типовых конфигурациях и на собеседованиях.

## Конвейер формирования отчёта

В уроке 19 мы видели схему. Теперь разберём её как цепочку объектов встроенного языка — по аналогии с заводом:

| Шаг | Объект | Аналогия | Что делает |
| --- | --- | --- | --- |
| 1 | `СхемаКомпоновкиДанных` + `НастройкиКомпоновкиДанных` | Чертёж и заказ | Что можно и что выбрал пользователь |
| 2 | `КомпоновщикМакетаКомпоновкиДанных` | Технолог | Из чертежа и заказа составляет **техзадание** — макет компоновки |
| 3 | `ПроцессорКомпоновкиДанных` | Станок | По техзаданию выполняет запросы, группирует, считает итоги |
| 4 | `ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент` | Упаковщик | Выкладывает готовый результат в табличный документ |

> [!info] Два разных «макета»
> **Макет компоновки** — это внутреннее техзадание для СКД, его не рисуют. Не путайте с **табличным макетом** печатной формы, который рисуют в Конфигураторе ([[01. Основы конфигурирования/24. Макеты и печатные формы|24. Макеты и печатные формы]]).

## Пример: тот же отчёт, но кодом

1. Открываем отчёт `ПродажиЗаПериодУчебный` → вкладка **Прочее** (или ПКМ по отчёту) → **Модуль объекта**.
2. `Ctrl+Alt+P` → выбираем событие `<ПриКомпоновкеРезультата>` → **Перейти**. Конфигуратор создаст заготовку с правильными параметрами.
3. Пишем код:

```1C
Процедура ПриКомпоновкеРезультата(ДокументРезультат, ДанныеРасшифровки, СтандартнаяОбработка)

    // 1. Отключаем стандартное формирование: дальше всё делает наш код
    СтандартнаяОбработка = Ложь;

    // 2. Берём схему и текущие настройки пользователя
    Схема = ПолучитьМакет("ОсновнаяСхемаКомпоновкиДанных");
    Настройки = КомпоновщикНастроек.ПолучитьНастройки();

    // 3. Технолог: схема + настройки → макет компоновки
    КомпоновщикМакета = Новый КомпоновщикМакетаКомпоновкиДанных;
    Макет = КомпоновщикМакета.Выполнить(Схема, Настройки, ДанныеРасшифровки);

    // 4. Станок: выполняет макет
    Процессор = Новый ПроцессорКомпоновкиДанных;
    Процессор.Инициализировать(Макет, , ДанныеРасшифровки);

    // 5. Упаковщик: выводит результат в табличный документ формы отчёта
    ДокументРезультат.Очистить();
    Вывод = Новый ПроцессорВыводаРезультатаКомпоновкиДанныхВТабличныйДокумент;
    Вывод.УстановитьДокумент(ДокументРезультат);
    Вывод.Вывести(Процессор);

КонецПроцедуры
```

Разберём параметры обработчика:

| Параметр | Что это |
| --- | --- |
| `ДокументРезультат` | Табличный документ на форме отчёта — сюда выводим результат |
| `ДанныеРасшифровки` | Сведения для **расшифровки**: двойной щелчок по ячейке отчёта открывает подробности. Передаём их по цепочке, чтобы расшифровка работала |
| `СтандартнаяОбработка` | `Истина` — платформа сформирует отчёт сама. Ставим `Ложь`, раз выводим сами |

И объекты, которые использует код:

| Код | Смысл |
| --- | --- |
| `ПолучитьМакет("ОсновнаяСхемаКомпоновкиДанных")` | Схема отчёта по имени макета — пишем точное имя из дерева |
| `КомпоновщикНастроек` | Свойство объекта отчёта: хранит настройки, которые сейчас выбрал пользователь (период, отборы) |
| `.ПолучитьНастройки()` | Берёт эти настройки, чтобы учесть выбор пользователя |

Код модуля объекта отчёта выполняется **на сервере** — поэтому здесь доступны запросы и все объекты СКД.

> [!warning] `СтандартнаяОбработка = Ложь` и пустой отчёт
> Если поставить `Ложь`, но забыть вывести результат (или ошибиться в цепочке), отчёт окажется **пустым** — платформа больше ничего не выводит сама. Сначала убедитесь, что стандартный отчёт работает, и только потом подключайте свой код.

## Зачем это всё, если результат тот же?

В этом примере результат действительно совпадает со стандартным — мы просто повторили то, что делает платформа. Но теперь между шагами можно вмешаться. Например, перед шагом 3 принудительно установить параметр:

```1C
Параметр = Настройки.ПараметрыДанных.НайтиЗначениеПараметра(Новый ПараметрКомпоновкиДанных("ДатаНачала"));
Если Параметр <> Неопределено Тогда
    Параметр.Значение = НачалоМесяца(ТекущаяДатаСеанса());
    Параметр.Использование = Истина;
КонецЕсли;
```

Или для набора «Объект» — передать таблицу значений в `Процессор.Инициализировать(Макет, ВнешниеНаборыДанных, …)`, где `ВнешниеНаборыДанных` — структура «имя набора → таблица».

Полное описание цепочки — в [руководстве разработчика 1С, раздел 10.7](https://1c-dn.com/download-trial/files/guides/developer_guide.pdf).

## Проверка

1. Сформируйте отчёт стандартно за октябрь, запишите итоги.
2. Добавьте обработчик `ПриКомпоновкеРезультата` с кодом выше, сформируйте с теми же параметрами — строки и суммы должны совпасть.
3. Закомментируйте строку `Вывод.Вывести(Процессор);` — отчёт станет пустым. Верните её.
4. Для практического отчёта этот обработчик не обязателен — после проверки его можно удалить.

> [!question]- Проверь себя
> 1. Что произойдёт, если установить `СтандартнаяОбработка = Ложь` и ничего не вывести?
> 2. Откуда берутся текущие настройки пользователя в коде отчёта?
> 3. Зачем передавать `ДанныеРасшифровки`?
>
> > [!success]- Ответы
> > 1. Отчёт будет пустым — платформа больше ничего не формирует.
> > 2. `КомпоновщикНастроек.ПолучитьНастройки()`.
> > 3. Чтобы работала расшифровка (клик по ячейке отчёта).
