> [!abstract] Коротко
> **Запрос** описывает, *какие данные получить* (а не как их обработать): поля, отбор, соединения, итоги. Источники — таблицы, которые платформа строит по объектам конфигурации: `Справочник.…`, `Документ.…`, `Документ.….ТабличнаяЧасть`, `РегистрНакопления.…` и **виртуальные таблицы** регистров. В запросе используются **имена** объектов, а не синонимы.

## Зачем нужен запрос?

Представьте, что руководитель спрашивает: «Сколько чайников мы продали в октябре и кому?». Ответ лежит в базе, но разбросан по десяткам накладных. Можно открыть каждую накладную и выписать строки на бумажку — долго и с ошибками. **Запрос** делает это за нас: мы *описываем, какой результат хотим получить*, а платформа сама находит нужные строки, складывает и сортирует их.

Простыми словами: запрос — это **вопрос к базе данных**, записанный по строгим правилам. Ответ на него — **таблица** (строки и колонки).

| Вопрос человеческими словами | Что делает запрос |
| --- | --- |
| «Покажи все товары по алфавиту» | Выбирает строки справочника и сортирует их |
| «Какие накладные дороже 1000 ₽?» | Отбирает строки по условию |
| «Сколько продали каждого товара за октябрь?» | Отбирает период и складывает количество по товарам |
| «Какие товары ни разу не продавались?» | Сопоставляет справочник с продажами и находит товары без пары |

## Язык запросов и встроенный язык — разные языки

В 1С два языка, и их важно не путать:

| | Встроенный язык (раздел 02) | Язык запросов (этот раздел) |
| --- | --- | --- |
| Для чего | **Действия**: посчитать, проверить, записать, показать сообщение | **Получение данных** из базы |
| Пример | `Если Сумма > 0 Тогда Сообщить("Есть"); КонецЕсли;` | `ВЫБРАТЬ Наименование ИЗ Справочник.Номенклатура` |
| Может изменить данные | Да: `Объект.Записать()` | **Нет**, только читает |

Язык запросов похож на SQL — если вы встречали SQL, многое будет знакомо. В запросе нельзя написать цикл `Для Каждого`, вызвать `Сообщить()` или записать документ. Обычно работа выглядит так: **встроенный язык** создаёт запрос, запускает его и что-то делает с полученной таблицей.

```mermaid
flowchart LR
    A["Код на встроенном языке<br/>создаёт запрос"] --> B["Платформа выполняет<br/>запрос к базе"]
    B --> C["Результат — таблица<br/>строк и колонок"]
    C --> D["Код обходит таблицу:<br/>показывает, считает, записывает"]
```

## Откуда берутся таблицы?

Мы не создаём таблицы базы вручную. Когда в разделе 01 мы добавили справочник `Номенклатура`, платформа **сама** создала для него таблицу. Каждому объекту конфигурации соответствует своя таблица, к которой можно обратиться в запросе:

| Имя таблицы в запросе | Откуда она взялась | Что означает **одна строка** |
| --- | --- | --- |
| `Справочник.Номенклатура` | Справочник «Номенклатура» | Один товар (или группа товаров) |
| `Документ.РасходнаяНакладная` | Документ «Расходная накладная» | Одна накладная — её шапка: номер, дата, покупатель |
| `Документ.РасходнаяНакладная.Товары` | Табличная часть «Товары» накладной | Одна строка товаров из какой-то накладной |
| `РегистрНакопления.Продажи` | Регистр накопления «Продажи» | Одно движение: «продали 2 чайника Иванову 05.10» |
| `РегистрНакопления.Продажи.Обороты(...)` | Платформа считает «на лету» | Итог продаж за период в нужном разрезе |

> [!tip] Главный вопрос перед каждым запросом
> «Что означает **одна строка** этой таблицы?» Если ответить на него заранее, вы избежите большинства ошибок раздела: удвоенных сумм, пропавших строк, лишних повторов.

Обратите внимание на имена: пишем **`Справочник`** в единственном числе, затем точку и **имя** объекта из дерева конфигурации — `Номенклатура`, а не синоним «Товары и услуги», который видит пользователь.

## Виртуальные таблицы

У регистров есть особые таблицы — **виртуальные**. Их нет в базе в готовом виде: платформа рассчитывает их в момент обращения. Например, `Продажи.Обороты` — это «сколько продали за выбранный период», уже сложенное по товарам и покупателям. Нам не нужно ни создавать, ни заполнять такую таблицу — достаточно попросить.

Простая аналогия: обычная таблица регистра — это **кассовая лента**, где записана каждая продажа. Виртуальная таблица оборотов — **итоговый отчёт кассира за смену**, который печатается по кнопке из той же ленты.

Набор виртуальных таблиц зависит от вида регистра: у оборотного регистра есть `Обороты`, у регистра остатков — ещё `Остатки` и `ОстаткиИОбороты`. Подробно — в [[16. Виртуальные таблицы регистров накопления]].

![[03-Конструктор-таблицы-и-поля.jpg]]

*Конструктор запроса учебной базы: в ветке «РегистрыНакопления» у оборотного регистра две таблицы — сама `Продажи` (движения) и виртуальная `Продажи.Обороты`.*

## На чём будем учиться?

Продолжаем учебную базу «1С:Купец» из первых разделов. Нам понадобятся:

| Объект | Вид | Что в нём есть |
| --- | --- | --- |
| `Номенклатура` | Справочник | Товары и услуги: `Код`, `Наименование`, `ВидНоменклатуры` |
| `Контрагенты` | Справочник | Покупатели |
| `РасходнаяНакладная` | Документ | Шапка: `Покупатель`, `ИтоговаяСумма`; табличная часть `Товары`: `Товар`, `Количество`, `Цена`, `Сумма` |
| `Продажи` | Регистр накопления (**оборотный**) | Измерения `Номенклатура`, `Контрагент`; ресурсы `Количество`, `Сумма` |

`ЦеныНоменклатуры` (регистр сведений) и регистр остатков `ТоварыНаСкладах` понадобятся только в отдельных примерах — их структуру укажем рядом. Для первых запросов достаточно справочника `Номенклатура`.

> [!warning] Заполните базу данными
> Запрос к пустой таблице вернёт пустой результат — и вы не поймёте, работает ли он. Перед уроками создайте в 1С:Предприятии 3–5 товаров, 2 покупателей и проведите 3–4 расходные накладные.

## Частые ошибки на старте

| Ошибка | Как правильно |
| --- | --- |
| `Справочники.Номенклатура` (множественное число) | В запросе — `Справочник.Номенклатура` |
| Синоним вместо имени: `Справочник.Товары` | Имя из дерева конфигурации: `Справочник.Номенклатура` |
| Ожидание, что запрос изменит данные | Запрос только читает; изменения — кодом на встроенном языке |

> [!question]- Проверь себя
> 1. Можно ли в запросе изменить документ?
> 2. Что означает одна строка `Документ.РасходнаяНакладная.Товары`?
> 3. Нужно ли заполнять виртуальную таблицу `Продажи.Обороты`?
>
> > [!success]- Ответы
> > 1. Нет, язык запросов только читает данные. Изменения — средствами встроенного языка.
> > 2. Одна строка табличной части «Товары» какого-то документа.
> > 3. Нет, её рассчитывает платформа при обращении.
