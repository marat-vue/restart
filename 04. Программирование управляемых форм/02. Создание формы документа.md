> [!abstract] Коротко
> Прежде чем создавать форму — проверяем, нет ли уже **основной формы документа**. Если нет: **Формы → Добавить → Форма документа**, назначаем основной, выбираем реквизиты. Затем проверяем пути к данным элементов, обновляем БД (`F7`) и открываем документ заново.

## Автоматическая и собственная форма

Если у документа нет своей формы, платформа строит её **автоматически** при каждом открытии: выводит все реквизиты и табличные части в стандартном порядке. Это удобно, но код в автоматическую форму не добавить — её нет в дереве конфигурации.

**Собственная** (созданная разработчиком) форма хранится в конфигурации. Её можно настроить мышкой и написать в ней код. Для всего раздела 04 нам нужна собственная форма документа `РасходнаяНакладная`.

## Шаг 1. Проверяем, нет ли формы уже

Прежде чем создавать, смотрим, что уже есть:

1. В дереве конфигурации — **Документы → РасходнаяНакладная** → двойной щелчок → вкладка **Формы**.
2. Вверху — три поля: **Документа**, **Списка**, **Выбора**. Это **основные** формы: какие формы платформа открывает по умолчанию.
3. Если в поле «Документа» уже указана форма — работаем в ней. Создавать вторую не нужно.

![[УФ-01-Формы-документа.png]]

*Вкладка «Формы» расходной накладной в «1С:Купец»: основные формы документа, списка и выбора, ниже — список всех форм документа.*

| Основная форма | Когда платформа её открывает |
| --- | --- |
| **Документа** | Пользователь открывает или создаёт документ |
| **Списка** | Пользователь открывает список документов из раздела |
| **Выбора** | Документ выбирают в поле другого объекта |

> [!warning] Не плодите формы
> Если создать вторую форму документа и писать код в неё, команда «Открыть» по-прежнему будет открывать **основную**. Код «не работает», а на самом деле он просто в другой форме. Сначала изучаем существующую форму.

## Шаг 2. Если формы ещё нет — создаём

1. На вкладке **Формы** документа — кнопка **Добавить** (или в дереве: узел **Формы** документа → **ПКМ → Добавить**).
2. Откроется **конструктор формы**. Тип — **Форма документа** (не списка и не выбора), имя — `ФормаДокумента`.
3. Ставим флажок **«Назначить форму основной»** — тогда платформа будет открывать именно её.
4. **Далее** → отмечаем реквизиты, которые попадут на форму: номер, дата, покупатель, договор, табличные части `Товары` и `Услуги`, итоговая сумма.
5. **Готово**. Откроется редактор формы: справа — основной реквизит `Объект`, слева — элементы для его полей.
6. Возвращаемся на вкладку **Формы** документа и проверяем: в поле «Документа» стоит `ФормаДокумента`.

## Шаг 3. Проверяем пути к данным

Каждое поле на форме должно быть связано с данными (о связи — [[01. Управляемая форма и её данные]]). Выделяем элемент в дереве и смотрим свойство **ПутьКДанным**:

| Элемент | Имя элемента (обычно) | ПутьКДанным |
| --- | --- | --- |
| Поле покупателя | `Покупатель` | `Объект.Покупатель` |
| Таблица товаров | `Товары` | `Объект.Товары` |
| Колонка количества | `ТоварыКоличество` | `Объект.Товары.Количество` |
| Колонка цены | `ТоварыЦена` | `Объект.Товары.Цена` |
| Колонка суммы | `ТоварыСумма` | `Объект.Товары.Сумма` |

Обратите внимание на **имена колонок**: платформа склеивает имя таблицы и имя реквизита — `Товары` + `Количество` = `ТоварыКоличество`. Эти имена понадобятся при настройке событий в следующих уроках.

Существующие элементы **не переименовываем**: на них может ссылаться код.

**Реквизит есть в документе, а на форме нет?** В правой панели раскрываем `Объект`, находим реквизит и **перетаскиваем** его мышью в дерево элементов слева — платформа создаст поле с правильным путём.

## Шаг 4. Модуль формы

Внизу редактора — вкладки **Форма** и **Модуль**. Модуль — это код **именно этой** формы. Модуль объекта документа (где проведение) — отдельный, здесь его кода нет.

Обработчик кнопки в модуле формы будет выглядеть так:

```1C
&НаКлиенте
Процедура ПоказатьИтогТоваров(Команда)
	// Действие кнопки
КонецПроцедуры
```

Сейчас его **не вставляем**: процедура сама по себе кнопку не создаёт. Связь «кнопка → команда → процедура» настроим в [[06. Команды формы и кнопки]].

## Шаг 5. Запуск и проверка

1. `Ctrl+S` — сохранить конфигурацию.
2. `F7` — обновить конфигурацию базы данных. Если платформа говорит, что база занята, — закройте открытое 1С:Предприятие и повторите.
3. `F5` — запустить 1С:Предприятие.
4. Откройте торговый раздел → список расходных накладных → **Создать** или существующую накладную.

Проверяем только расположение полей — записывать и проводить пока не нужно.

> [!warning] Открытое окно показывает старую версию
> Если 1С:Предприятие было открыто во время `F7`, уже открытые окна показывают прежнее состояние формы. Закройте документ и откройте заново, а лучше перезапустите Предприятие.

## Если результат отличается

| Симптом | Причина | Что сделать |
| --- | --- | --- |
| Открывается прежняя форма | Новая не назначена основной или не обновлена БД | Вкладка «Формы» документа → поле «Документа»; `F7` |
| Нет нового реквизита документа | В собственной форме реквизиты не появляются сами | Перетащить из `Объект` в дерево элементов |
| Нет команды документа в разделе | Документ не включён в подсистему | Вкладка «Подсистемы» документа |
| Форма похожа на список | Создан не тот тип формы | Удалить и создать «Форма документа» |

> [!question]- Проверь себя
> 1. Документ открывается не той формой, в которую вы писали код. Почему?
> 2. Добавили реквизит в документ. Появится ли он в собственной форме сам?
>
> > [!success]- Ответы
> > 1. Ваша форма не назначена основной.
> > 2. Нет, его нужно перетащить в дерево элементов.
