> [!abstract] Коротко
> Проверку делаем на двух уровнях: **в форме** — чтобы подсказать пользователю до записи, **в `ПередЗаписью` модуля объекта** — чтобы запретить некорректную запись и из формы, и из кода (`Отказ = Истина`). `ОбработкаПроверкиЗаполнения` вызывается механизмом проверки заполнения, а не каждым программным `Записать()`. Сообщение к полю: `СообщениеПользователю` с `Поле` и `ПутьКДанным`/`УстановитьДанные()`.

## Зачем проверять дважды

Правила нашей накладной: покупатель обязателен; в каждой строке товаров выбран товар, количество больше нуля, цена не отрицательная. Пустую табличную часть `Товары` не запрещаем — в накладной могут быть только услуги.

Проверять будем на **двух уровнях**, и у каждого своя роль:

| Уровень | Где | Задача | Аналогия |
| --- | --- | --- | --- |
| **Форма** | Модуль формы, на клиенте | **Подсказать** пользователю до записи, подсветить поле с ошибкой | Продавец на кассе: «Вы забыли пакет» |
| **Объект** | Модуль объекта, `ПередЗаписью` | **Запретить** запись неверных данных — из формы, из обработки, из обмена | Охранник на выходе: без чека не выпустит |

Проверки в форме удобны, но обходятся: документ можно записать без формы (кодом, загрузкой). Поэтому **обязательное** правило всегда дублируем в модуле объекта. Проверки в форме — для удобства, в объекте — для гарантии.

## Заполненность ≠ правильность

У реквизита в конфигурации есть свойство **«Проверка заполнения: Выдавать ошибку»** ([[01. Основы конфигурирования/22. Предопределённые данные и заполнение|22. Предопределённые данные и заполнение]]). Оно проверяет только «не пусто». Количество −5 — заполнено, но недопустимо. Поэтому для правил вида «больше нуля» нужен свой код.

Красное подчёркивание пустого поля в форме — только подсказка интерфейса. Программный `Записать()` не обязан выполнять проверки формы. Подробнее — [руководство 1С, 5.6.12](https://1c-dn.com/library/tutorials/1c_enterprise_developer_guide_8_3_27/?sphrase_id=1808293).

## Сообщение, привязанное к полю

`Сообщить("Текст")` выводит сообщение внизу окна, но не показывает, **где** ошибка. Для понятного сообщения используют объект `СообщениеПользователю`: при щелчке по такому сообщению платформа переводит курсор на поле с ошибкой и подсвечивает его.

```1C
&НаКлиенте
Процедура ПоказатьОшибкуФормы(ТекстСообщения, ИмяПоля)

	Сообщение = Новый СообщениеПользователю;
	Сообщение.Текст = ТекстСообщения;
	Сообщение.ПутьКДанным = "Объект";
	Сообщение.Поле = ИмяПоля;           // путь ВНУТРИ Объект: "Покупатель", "Товары[0].Количество"
	Сообщение.Сообщить();

КонецПроцедуры
```

| Свойство | Значение | Смысл |
| --- | --- | --- |
| `Текст` | «Выберите покупателя» | Что увидит пользователь |
| `ПутьКДанным` | `"Объект"` | Какой реквизит формы содержит ошибочные данные |
| `Поле` | `"Покупатель"` или `"Товары[0].Количество"` | Путь **внутри** этого реквизита — к конкретному полю или ячейке |

`Поле` — путь к **данным**, а не имя элемента: `"Покупатель"`, а не `"ПолеПокупателя"`, и без второго `Объект.`. Для ячейки таблицы указываем строку в квадратных скобках: `"Товары[0].Количество"` — количество в **первой** строке. Индекс начинается с 0, а номер строки для пользователя — с 1. См. [статью 1С о сообщениях](https://1c-dn.com/library/messages_displayed_to_users/).

## Проверка в форме

Функция проходит по правилам и при первой ошибке показывает сообщение у нужного поля:

```1C
&НаКлиенте
Функция ПроверитьДанныеФормы()

	Если НЕ ЗначениеЗаполнено(Объект.Покупатель) Тогда
		ПоказатьОшибкуФормы("Выберите покупателя", "Покупатель");
		Возврат Ложь;
	КонецЕсли;

	Для Каждого СтрокаТовара Из Объект.Товары Цикл
		Индекс = Объект.Товары.Индекс(СтрокаТовара);
		Путь = СтрШаблон("Товары[%1].", Индекс);
		НомерСтроки = Индекс + 1;

		Если НЕ ЗначениеЗаполнено(СтрокаТовара.Товар) Тогда
			ПоказатьОшибкуФормы(СтрШаблон("Строка %1: выберите товар", НомерСтроки), Путь + "Товар");
			Возврат Ложь;
		ИначеЕсли СтрокаТовара.Количество <= 0 Тогда
			ПоказатьОшибкуФормы(СтрШаблон("Строка %1: количество должно быть больше нуля", НомерСтроки), Путь + "Количество");
			Возврат Ложь;
		ИначеЕсли СтрокаТовара.Цена < 0 Тогда
			ПоказатьОшибкуФормы(СтрШаблон("Строка %1: цена не может быть отрицательной", НомерСтроки), Путь + "Цена");
			Возврат Ложь;
		КонецЕсли;
	КонецЦикла;

	Возврат Истина;

КонецФункции
```

Разберём ключевые строки:

| Код | Что делает |
| --- | --- |
| `ЗначениеЗаполнено(Объект.Покупатель)` | `Ложь`, если покупатель не выбран (пустая ссылка) |
| `Объект.Товары.Индекс(СтрокаТовара)` | Номер строки в коллекции, начиная с 0 |
| `Путь = "Товары[0]."` | Начало пути к ячейке этой строки |
| `Путь + "Количество"` | Готовый путь: `"Товары[0].Количество"` |
| `Возврат Ложь` | Нашли ошибку — дальше не проверяем, сообщаем о первой |
| `Возврат Истина` | Ошибок нет |

Функция **сообщает** об ошибке и **не исправляет** данные молча: если подставить вместо нуля единицу, пользователь не узнает, что ошибся.

Временная команда «Проверить» для экспериментов:

```1C
&НаКлиенте
Процедура ПроверитьДокументУчебно(Команда)
	Если ПроверитьДанныеФормы() Тогда
		Сообщить("Проверки пройдены");
	КонецЕсли;
КонецПроцедуры
```

## Обязательная проверка в модуле объекта

Теперь гарантия. Открываем **модуль объекта** документа (ПКМ по документу → «Открыть модуль объекта»). Здесь реквизиты доступны напрямую — `Покупатель`, `Товары`, без `Объект.`, — а директив `&НаКлиенте`/`&НаСервере` нет: модуль объекта всегда выполняется на сервере.

```1C
Процедура ПередЗаписью(Отказ, РежимЗаписи, РежимПроведения)

	Если Отказ Тогда
		Возврат;
	КонецЕсли;

	Если НЕ ДанныеКорректны() Тогда
		Отказ = Истина;
		Возврат;
	КонецЕсли;

	// Существующие расчёты и логика документа

КонецПроцедуры

Функция ДанныеКорректны()

	Если НЕ ЗначениеЗаполнено(Покупатель) Тогда
		СообщитьОбОшибке("Выберите покупателя", "Покупатель");
		Возврат Ложь;
	КонецЕсли;

	Для Каждого СтрокаТовара Из Товары Цикл
		Путь = СтрШаблон("Товары[%1].", СтрокаТовара.НомерСтроки - 1);
		Если НЕ ЗначениеЗаполнено(СтрокаТовара.Товар) Тогда
			СообщитьОбОшибке(СтрШаблон("Строка %1: выберите товар", СтрокаТовара.НомерСтроки), Путь + "Товар");
			Возврат Ложь;
		ИначеЕсли СтрокаТовара.Количество <= 0 Тогда
			СообщитьОбОшибке(СтрШаблон("Строка %1: количество должно быть больше нуля", СтрокаТовара.НомерСтроки), Путь + "Количество");
			Возврат Ложь;
		ИначеЕсли СтрокаТовара.Цена < 0 Тогда
			СообщитьОбОшибке(СтрШаблон("Строка %1: цена не может быть отрицательной", СтрокаТовара.НомерСтроки), Путь + "Цена");
			Возврат Ложь;
		КонецЕсли;
	КонецЦикла;

	Возврат Истина;

КонецФункции

Процедура СообщитьОбОшибке(ТекстСообщения, ИмяПоля)
	Сообщение = Новый СообщениеПользователю;
	Сообщение.Текст = ТекстСообщения;
	Сообщение.Поле = ИмяПоля;
	Сообщение.УстановитьДанные(ЭтотОбъект);  // связь с объектом — платформа сопоставит его с формой
	Сообщение.Сообщить();
КонецПроцедуры
```

Отличия от проверки в форме:

| | В форме | В модуле объекта |
| --- | --- | --- |
| Доступ к данным | `Объект.Покупатель` | `Покупатель` — напрямую |
| Номер строки | Вычисляем через `Индекс()` | Есть стандартный `НомерСтроки` (с 1) |
| Привязка сообщения | `ПутьКДанным = "Объект"` | `УстановитьДанные(ЭтотОбъект)` — «ошибка в этом объекте» |
| Результат ошибки | Подсказка | **Запись отменяется**: `Отказ = Истина` |

> [!warning] `Отказ`, а не `Возврат`
> `Отказ = Истина` останавливает запись; один `Возврат` — **нет**, документ запишется. `Отказ = Ложь` никогда не пишем: его могла выставить другая проверка. Существующий `ПередЗаписью` дополняем, а не создаём второй.

> [!tip] Альтернатива — `ОбработкаПроверкиЗаполнения`
> Это событие модуля объекта вызывается при интерактивной записи и при явном `ПроверитьЗаполнение()`; в нём удобно добавлять свои проверки к стандартной «Проверке заполнения» реквизитов. При программной записи документа **без проведения** (`Записать()` или `Записать(РежимЗаписиДокумента.Запись)`) оно само не вызывается; при программном проведении (`РежимЗаписиДокумента.Проведение`) платформа проверку заполнения выполняет. Для правил, которые должны действовать при **любой** записи, надёжнее `ПередЗаписью`.

## Проверяем по очереди

1. Пустой покупатель → «Проверить» → сообщение; щёлкните по нему — курсор перейдёт к полю покупателя.
2. Строка без товара → сообщение у колонки товара.
3. Количество 0 → сообщение о количестве.
4. Отрицательная цена → сообщение о цене (если тип реквизита допускает отрицательные числа).
5. Некорректная накладная, кнопка **«Записать»** → серверная проверка запрещает запись даже без «Проверить».

Сообщение есть, а документ записался — ищите, где не установлен `Отказ`. Поле не подсвечивается — проверьте путь в `Поле` и индекс строки.

> [!question]- Проверь себя
> 1. Почему проверки в форме недостаточно?
> 2. Что указывается в `Сообщение.Поле`: имя элемента или путь к данным?
> 3. Для строки с `НомерСтроки = 3` — какой путь в `Поле`?
>
> > [!success]- Ответы
> > 1. Запись из кода, обработок и обменов проходит без формы.
> > 2. Путь к данным (`Покупатель`, `Товары[2].Количество`).
> > 3. `Товары[2]` — индекс с нуля.
