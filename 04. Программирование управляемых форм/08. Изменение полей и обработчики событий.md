> [!abstract] Коротко
> Реакция на ввод — обработчик **ПриИзменении** у поля или колонки (свойства → «События»). Срабатывает при **интерактивном** изменении и завершении ввода, а не при каждом нажатии клавиши и не при программном присваивании. Параметр `Элемент` — поле формы; данные строки берём из `Элементы.Товары.ТекущиеДанные`.

## Задача: пересчитать сумму при вводе

Пользователь вводит в строку товара количество 2 и цену 150 — и ожидает, что сумма **сама** станет 300. Для этого нужно выполнить код в момент, когда пользователь изменил количество или цену. Такой момент — событие **ПриИзменении** у поля.

У каждого поля и колонки формы есть свои события. Самые нужные:

| Событие | Когда происходит |
| --- | --- |
| **ПриИзменении** | Пользователь изменил значение и **завершил ввод** (нажал `Tab`, `Enter` или перешёл в другое поле) |
| **НачалоВыбора** | Пользователь нажал кнопку выбора «…» у поля |
| **ОбработкаВыбора** | В поле вернулось значение из окна выбора |

Важно: `ПриИзменении` срабатывает **не на каждое нажатие клавиши**, а когда ввод закончен. Пока вы набираете «1», «12», «125» — события нет; нажали `Tab` — событие одно, со значением 125.

## Шаг 1. Создаём обработчик

1. Открываем `ФормаДокумента` → вкладка **Форма** → в дереве элементов раскрываем таблицу `Товары`.
2. Выделяем **колонку** `ТоварыКоличество` (путь к данным `Объект.Товары.Количество`).
3. Палитра свойств → раздел **События** → строка **ПриИзменении** → кнопка с лупой.
4. Выбираем **«Создать на клиенте»**.

![[УФ-09-Событие-ПриИзменении.png]]

*Свойства колонки таблицы и событие «ПриИзменении». Если обработчик уже назначен — кнопка перейдёт к нему.*

Конфигуратор создаст заготовку и сам впишет её имя в свойство события:

```1C
&НаКлиенте
Процедура ТоварыКоличествоПриИзменении(Элемент)

КонецПроцедуры
```

Имя процедуры собрано из имени элемента и события: `ТоварыКоличество` + `ПриИзменении`. Параметры подставлены правильные — у разных событий они разные, поэтому заготовку всегда создаём кнопкой, а не пишем вручную.

## Шаг 2. Убеждаемся, что событие срабатывает

Сначала проверим связь, а уже потом будем считать. Пишем в обработчик:

```1C
&НаКлиенте
Процедура ТоварыКоличествоПриИзменении(Элемент)

	СтрокаТовара = Элементы.Товары.ТекущиеДанные;
	Если СтрокаТовара = Неопределено Тогда
		Возврат;
	КонецЕсли;

	Сообщить("Новое количество: " + СтрокаТовара.Количество);

КонецПроцедуры
```

| Строка | Что делает |
| --- | --- |
| `Элементы.Товары.ТекущиеДанные` | Данные **той строки** таблицы, где сейчас курсор, — то есть строки, которую пользователь меняет |
| `Если … = Неопределено Тогда Возврат` | Защита: если текущей строки нет, выходим, чтобы не получить ошибку |
| `СтрокаТовара.Количество` | Количество в этой строке — уже **новое**, введённое значение |

> [!warning] Параметр `Элемент` — это поле, а не значение
> Платформа передаёт в `Элемент` **само поле формы** (колонку `ТоварыКоличество`), а не введённое число. Поэтому `Элемент.Количество` — ошибка. Значение берём из данных строки: `Элементы.Товары.ТекущиеДанные.Количество`.

**Проверка:** `Ctrl+S` → `F7` → откройте накладную **заново** → введите количество в строке и нажмите `Tab`. Должно появиться сообщение «Новое количество: …». Пока ввод не завершён, сообщения нет.

## Шаг 3. Считаем сумму строки

Связь работает — заменяем сообщение на расчёт:

```1C
&НаКлиенте
Процедура ТоварыКоличествоПриИзменении(Элемент)

	СтрокаТовара = Элементы.Товары.ТекущиеДанные;
	Если СтрокаТовара = Неопределено Тогда
		Возврат;
	КонецЕсли;

	СтрокаТовара.Сумма = Окр(СтрокаТовара.Количество * СтрокаТовара.Цена, 2);

КонецПроцедуры
```

`ТекущиеДанные` — это не копия, а сама строка данных формы. Присваивание `СтрокаТовара.Сумма = …` сразу меняет строку, и колонка «Сумма» на экране обновится. `Окр(…, 2)` округляет до копеек ([[02. Программирование/05. Работа с числами|05. Работа с числами]]).

Для колонки `ТоварыЦена` создаём **такой же** обработчик `ТоварыЦенаПриИзменении` — сумма должна пересчитываться и при смене цены. Чтобы не копировать формулу дважды, в [[10. Пересчёт строк и итога товаров]] вынесем расчёт в отдельную процедуру.

## Программное присваивание — не событие

`ПриИзменении` срабатывает только когда значение меняет **пользователь в форме**. Если код сам пишет `СтрокаТовара.Количество = 5`, событие **не** произойдёт. Отсюда два правила:

- при программном заполнении строки (например, подбором) расчёт вызываем **явно**;
- обработчик формы не защищает документ, который записали обработкой или обменом без формы. Обязательный пересчёт дублируем в модуле объекта ([[13. Запись из формы и события записи]]).

## Если не срабатывает

1. В свойстве **ПриИзменении** нужной колонки указано имя процедуры (а не пусто).
2. В модуле нет второй процедуры с тем же именем.
3. Меняете именно ту колонку, у которой назначено событие, и завершаете ввод `Tab`.
4. База обновлена (`F7`), форма открыта **заново**.
5. Для точки останова — Предприятие запущено в режиме отладки (`F5`).

| Сообщение об ошибке | Причина |
| --- | --- |
| «Поле объекта не обнаружено (Товары)» у `Элементы.Товары` | Неверное **имя элемента** таблицы — проверьте свойство «Имя» |
| «Поле объекта не обнаружено (Количество)» у `СтрокаТовара.Количество` | Неверное имя реквизита табличной части |

> [!question]- Проверь себя
> 1. Что передаётся в параметре `Элемент`?
> 2. Вызовется ли `ПриИзменении`, если код выполнит `Строка.Количество = 3`?
> 3. Можно ли назначить одну процедуру событиям двух колонок?
>
> > [!success]- Ответы
> > 1. Поле формы, в котором произошло изменение.
> > 2. Нет, событие — только для интерактивного ввода.
> > 3. Да, если у событий одинаковая сигнатура.
