> [!abstract] Коротко
> Расположение элементов задаёт **дерево**: обычные **группы** объединяют поля (вертикально или горизонтально), группа **Страницы** со вложенными **Страница** раскладывает блоки по вкладкам. Группы меняют только интерфейс — данные остаются на месте. Для размещения код не нужен.

## Как платформа раскладывает элементы

В управляемой форме мы не задаём координаты полей. Расположение определяет **дерево элементов**: что внутри чего лежит и в каком порядке. Платформа читает дерево сверху вниз и выводит элементы.

Чтобы управлять раскладкой, используют **группы** — «контейнеры» для элементов. Аналогия — **коробки на полке**: можно сложить несколько вещей в одну коробку, поставить коробки рядом или друг на друга, а можно сделать «картотеку» с вкладками-разделителями.

| Вид группы | Как выглядит | Для чего |
| --- | --- | --- |
| **Обычная группа**, группировка «Вертикальная» | Элементы друг под другом | Блок «Данные накладной» с рамкой и заголовком |
| **Обычная группа**, группировка «Горизонтальная» | Элементы в одну строку | Номер и дата рядом |
| **Страницы** | Набор вкладок | Переключение «Товары / Услуги» |
| **Страница** | Одна вкладка внутри «Страниц» | Содержимое вкладки «Товары» |

Группы меняют **только внешний вид**. Данные документа от них не меняются.

## Дерево определяет вложенность

![[УФ-05-Дерево-элементов.png]]

*Дерево элементов формы: колонки `ТоварыТовар`, `ТоварыКоличество`… вложены в таблицу `Товары`.*

Переносим таблицу — переносится весь её блок со всеми колонками. Переносим одну колонку — меняется устройство таблицы. Перед перетаскиванием проверяем, **что именно** выделено.

> [!warning] Группы — только интерфейс
> Создание страницы не создаёт табличную часть, а перенос таблицы на другую страницу не меняет `Объект.Товары`. Мы лишь раскладываем поля по «коробкам».

## Шаг 1. Группа шапки

Если подходящей группы ещё нет:

1. В дереве элементов выделяем корень **Форма** → **ПКМ → Добавить** (или кнопка «Добавить» над деревом).
2. В окне выбора — **Группа — обычная группа**.
3. В свойствах группы:
   - **Имя** — `ГруппаШапкаУчебная` (для кода);
   - **Заголовок** — «Данные накладной» (видит пользователь);
   - **Группировка** — Вертикальная.
4. Перетаскиваем в группу **существующие** поля номера, даты и покупателя. Не создаём новые поля — у перенесённых сохранится `ПутьКДанным`.

**Номер и дата в одну строку:** внутри `ГруппаШапкаУчебная` добавляем ещё одну обычную группу с **горизонтальной** группировкой и переносим в неё поля номера и даты.

## Шаг 2. Страницы «Товары» и «Услуги»

1. После группы шапки: **Добавить → Группа — Страницы**, имя `СтраницыСоставУчебные`.
2. Выделяем `СтраницыСоставУчебные` → **Добавить → Группа — Страница**, имя `СтраницаТоварыУчебная`, заголовок «Товары».
3. Так же — вторая страница `СтраницаУслугиУчебная`, заголовок «Услуги».
4. Перетаскиваем таблицу `Товары` и поле `ИтогТоваров` на первую страницу, таблицу `Услуги` — на вторую.

Должно получиться дерево:

```text
Форма
├─ ГруппаШапкаУчебная          ← обычная группа «Данные накладной»
│  ├─ (группа номер + дата)    ← горизонтальная
│  └─ Покупатель
├─ СтраницыСоставУчебные        ← группа «Страницы»
│  ├─ СтраницаТоварыУчебная    ← вкладка «Товары»
│  │  ├─ Товары
│  │  │  └─ колонки…
│  │  └─ ИтогТоваров
│  └─ СтраницаУслугиУчебная    ← вкладка «Услуги»
│     └─ Услуги
└─ общий итог документа        ← вне страниц: виден всегда
```

А на экране пользователь увидит:

```text
┌ Данные накладной ─────────────────────┐
│ Номер: [000000001]   Дата: [05.10.2026]│
│ Покупатель: [Ромашка               ]   │
└────────────────────────────────────────┘
 [ Товары ] [ Услуги ]
┌────────────────────────────────────────┐
│ Товар      Количество   Цена   Сумма   │
│ Чайник          2        150    300    │
│ Итого товаров: 300                     │
└────────────────────────────────────────┘
Итоговая сумма: 450
```

**Имя** группы нужно для кода, **заголовок** видит пользователь. Используем понятные идентификаторы без пробелов, в стиле ВерблюжийРегистр.

`ИтогТоваров` относится только к товарам — поэтому он на странице товаров. Общий итог документа (`ИтоговаяСумма`, с услугами) оставляем **вне** страниц, чтобы он был виден на любой вкладке, и не меняем его путь на `ИтогТоваров`.

## Группы в коде

Код для раскладки не нужен — всё делается мышкой. Но к группе можно обратиться по имени, как к любому элементу:

```1C
Элементы.ГруппаШапкаУчебная.Видимость = Ложь;   // скрыть весь блок шапки целиком
```

Поэтому имя группы должно быть уникальным и осмысленным: `Группа1` через месяц никто не узнает.

## Проверка

`Ctrl+S` → `F7` → открываем накладную **заново**:
1. Поля шапки на месте, в рамке «Данные накладной», номер и дата в одной строке.
2. На вкладке «Товары» — таблица и итог; на «Услугах» — таблица услуг.
3. Общий итог документа виден при переключении вкладок.
4. Растяните и сузьте окно — форма остаётся удобной.

| Симптом | Что проверить |
| --- | --- |
| Пустая вкладка | Есть ли элементы **внутри** страницы (а не рядом с ней) |
| Вместо вкладок — обычный блок | Вид родительской группы — «Страницы», а не «Обычная группа» |
| Пропали колонки таблицы | Не перенесли ли колонку вместо всей таблицы |
| Поле пустое после переноса | Создали новое поле вместо переноса существующего — нет `ПутьКДанным` |

> [!question]- Проверь себя
> 1. Перенесли таблицу `Услуги` на страницу. Изменилась ли табличная часть документа?
> 2. Как расположить номер и дату в одной строке?
> 3. Почему общий итог лучше держать вне страниц?
>
> > [!success]- Ответы
> > 1. Нет, изменилось только размещение элемента.
> > 2. Поместить их в обычную группу с горизонтальной группировкой.
> > 3. Он виден при переключении между вкладками.
