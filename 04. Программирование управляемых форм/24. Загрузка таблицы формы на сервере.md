> [!abstract] Коротко
> Чтобы показать на форме результат запроса: реквизит формы типа **ТаблицаЗначений** с заранее объявленными колонками → таблица на форме → серверная процедура (`&НаСервере`) выполняет запрос и вызывает `ЗначениеВРеквизитФормы(Таблица, "Результаты")`. На клиенте данные этого реквизита — `ДанныеФормыКоллекция`, а не таблица значений.

## Показать на форме результат запроса

В разделе 03 мы получали результат запроса в таблицу значений и выводили его через `Сообщить()`. Удобнее показать его **таблицей на форме**. Для этого:

1. Создаём реквизит формы типа **ТаблицаЗначений** — «контейнер» для строк — и заранее описываем его колонки.
2. Выводим реквизит на форму — получается таблица на экране.
3. На **сервере** выполняем запрос и перекладываем результат в реквизит.

Почему на сервере? Запрос выполняется только там ([[03. Язык запросов и СКД/02. Первый запрос в конструкторе и в коде|02. Первый запрос]]), а перекладка в реквизит требует данных формы — значит, `&НаСервере`.

Создаём общую форму `ТоварыУчебные` с таблицей номенклатуры и кнопкой «Обновить товары». Ничего не записываем. Для больших рабочих списков удобнее [[19. Форма списка и динамический список|динамический список]]; здесь — явная загрузка ограниченного набора.

## Реквизит и таблица

1. **Общие → Общие формы → Добавить** `ТоварыУчебные`.
2. Реквизит `Результаты`, тип **ТаблицаЗначений**.
3. Колонки **внутри** `Результаты`: `Товар` (`СправочникСсылка.Номенклатура`), `Наименование` (Строка 100). Имена = псевдонимам запроса.
4. Перетаскиваем `Результаты` в элементы, включаем у таблицы **ТолькоПросмотр**.

| Элемент | ПутьКДанным |
| --- | --- |
| Таблица | `Результаты` |
| Колонки | `Результаты.Товар`, `Результаты.Наименование` |

`Товар` — ссылка (идентификатор), `Наименование` — текст: одинаковые названия не делают товары одной записью.

## Команда обновления

```1C
&НаКлиенте
Процедура ОбновитьТовары(Команда)
	ЗагрузитьТоварыНаСервере();
КонецПроцедуры

&НаСервере
Процедура ЗагрузитьТоварыНаСервере()

	Запрос = Новый Запрос(
	"ВЫБРАТЬ ПЕРВЫЕ 100
	|	Н.Ссылка КАК Товар,
	|	Н.Наименование КАК Наименование
	|ИЗ
	|	Справочник.Номенклатура КАК Н
	|ГДЕ
	|	НЕ Н.ЭтоГруппа
	|	И НЕ Н.ПометкаУдаления
	|УПОРЯДОЧИТЬ ПО
	|	Наименование");

	ТаблицаТоваров = Запрос.Выполнить().Выгрузить();
	ЗначениеВРеквизитФормы(ТаблицаТоваров, "Результаты");

КонецПроцедуры
```

Для неиерархического справочника убираем `НЕ Н.ЭтоГруппа` — такого поля нет. `ПЕРВЫЕ 100` — это не постраничный вывод, а ограничение: остальные товары не попадут.

## Три уровня одной таблицы

| Выражение | Что это |
| --- | --- |
| `ТаблицаТоваров` в серверной процедуре | Обычная `ТаблицаЗначений` на сервере |
| `Результаты` | Данные формы, `ДанныеФормыКоллекция` |
| `Элементы.Результаты` | Таблица интерфейса |

Методы таблицы значений нельзя автоматически применять к `Результаты` — см. [пособие 1С о типах данных формы](https://kb.1ci.com/1C_Enterprise_Platform/Tutorials/Practical_developer_guide_8.3/Lesson_27._Form_development_techniques/Form_data_types/). `ЗначениеВРеквизитФормы` требует контекста формы — `&НаСервере`, а не без контекста.

## Открытие и проверка

Из формы накладной: `ОткрытьФорму("ОбщаяФорма.ТоварыУчебные");`.

- После «Обновить товары» — до 100 строк по алфавиту, без групп и помеченных.
- Повторное нажатие **заменяет** набор, а не удваивает.
- До первого нажатия таблица пустая; для автозагрузки вызываем процедуру из `ПриСозданииНаСервере`.
- Запрос выполняется с правами пользователя — у ограниченной роли строк может быть меньше.

> [!question]- Проверь себя
> 1. Почему процедура загрузки — `&НаСервере`, а не `&НаСервереБезКонтекста`?
> 2. Что будет, если колонки реквизита назвать иначе, чем поля запроса?
> 3. Чем такая таблица хуже динамического списка для 100 000 товаров?
>
> > [!success]- Ответы
> > 1. `ЗначениеВРеквизитФормы` изменяет реквизит формы — нужен её контекст.
> > 2. Значения не попадут в колонки — сопоставление идёт по именам.
> > 3. Загружает весь набор в форму сразу; динамический список читает порциями.
