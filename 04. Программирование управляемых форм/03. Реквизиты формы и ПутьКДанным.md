> [!abstract] Коротко
> Кроме `Объект`, у формы могут быть **собственные реквизиты** — временные данные окна (итог, флажок, значение для отбора). В базу они **не записываются**. Путь к ним — без `Объект.`: `ИтогТоваров`. В коде значение присваиваем реквизиту (`ИтогТоваров = 600`), а оформление меняем у элемента (`Элементы.ИтогТоваров.ТолькоПросмотр = Истина`).

## Зачем форме свои реквизиты

`Объект` содержит то, что **хранится** в документе: покупатель, строки товаров. Но форме часто нужны и **временные** данные, которые в базу записывать не надо:

- итог по одним только товарам (без услуг) — чтобы показать пользователю;
- флажок «Показывать итог» — чтобы скрывать или показывать поле;
- значение для поиска или отбора.

Для этого у формы есть **собственные реквизиты**. Они живут, пока открыто окно, и исчезают при его закрытии.

Аналогия: документ — это бланк накладной, а реквизиты формы — **пометки карандашом на полях** бланка. Они помогают при работе, но в архив не попадают.

## Реквизит объекта или реквизит формы

![[УФ-03-Реквизиты-объекта.png]]

*Реквизиты формы накладной: `Объект` раскрыт — внутри поля документа и табличные части. Собственные реквизиты формы будут на одном уровне с `Объект`.*

| Данные | Где определены | Путь к ним | При записи документа |
| --- | --- | --- | --- |
| `Объект.Покупатель` | Реквизит **документа** в дереве конфигурации | `Объект.Покупатель` | **Записывается** в базу |
| `ИтогТоваров` | Реквизит **формы** на вкладке «Реквизиты» | `ИтогТоваров` | **Не записывается** |

Правило выбора простое:
- значение нужно **сохранять** и видеть после повторного открытия документа → реквизит **документа** (в дереве конфигурации);
- значение нужно только **пока открыто окно** → реквизит **формы**.

## Шаг 1. Создаём реквизит `ИтогТоваров`

1. В редакторе формы справа открываем вкладку **Реквизиты**.
2. Выделяем **верхний уровень** — пустое место или сам список, а **не** строку внутри `Объект`. Иначе реквизит попадёт не туда.
3. Кнопка **Добавить** (зелёный плюс).
4. В свойствах нового реквизита:
   - **Имя** — `ИтогТоваров`;
   - **Тип** — Число, длина 15, точность 2;
   - **Заголовок** — «Итого товаров».
5. Флажок **Основной реквизит** не трогаем — основным остаётся `Объект`.

## Шаг 2. Выводим реквизит на форму

Реквизит — это данные. Чтобы пользователь их **увидел**, нужен элемент.

1. Перетаскиваем `ИтогТоваров` мышью из правой панели в дерево элементов слева — и отпускаем **после** таблицы `Товары` (на одном уровне с ней).
2. Платформа создаст поле. Проверяем у него в свойствах:
   - **Имя** = `ИтогТоваров`;
   - **ПутьКДанным** = `ИтогТоваров` — без `Объект.`!
3. Включаем у поля свойство **ТолькоПросмотр**: итог считает программа, пользователь его не вводит.

![[УФ-04-Путь-к-данным.png]]

*Свойства элемента: «ПутьКДанным» связывает поле с реквизитом. Для нашего поля путь — `ИтогТоваров`, без `Объект.`.*

Почему без `Объект.`? Потому что `ИтогТоваров` лежит **рядом** с `Объект`, а не внутри него:

```text
Реквизиты формы
├─ Объект             ← данные документа
│  ├─ Покупатель      → путь: Объект.Покупатель
│  └─ Товары          → путь: Объект.Товары
└─ ИтогТоваров        → путь: ИтогТоваров
```

## Шаг 3. Присваиваем значение в коде

В модуле формы реквизит формы доступен **просто по имени**, как переменная:

```1C
// Внутри процедуры модуля этой формы
ИтогТоваров = Объект.Товары.Итог("Сумма");
```

Разберём:

| Часть | Что это |
| --- | --- |
| `ИтогТоваров` | Реквизит формы — присваиваем ему значение |
| `Объект.Товары` | Строки табличной части «Товары» в данных формы |
| `.Итог("Сумма")` | Метод коллекции: сумма колонки «Сумма» по всем строкам |

Поле на экране, связанное с `ИтогТоваров`, **само** покажет новое значение — обновлять его вручную не нужно. В этом и смысл связи «данные → элемент».

Этот код **складывает уже рассчитанные** суммы строк, но не пересчитывает сами строки (`Количество × Цена`) — это сделаем в [[10. Пересчёт строк и итога товаров]]. Куда именно поместить эту строку — в обработчик кнопки ([[06. Команды формы и кнопки]]) и в событие открытия формы ([[07. Создание, открытие и закрытие формы]]).

## Частые ошибки

| Неверно | Почему | Верно |
| --- | --- | --- |
| `Объект.ИтогТоваров = 600` | У документа нет такого реквизита — ошибка «Поле объекта не обнаружено» | `ИтогТоваров = 600` |
| `Элементы.ИтогТоваров = 600` | `Элементы.ИтогТоваров` — это поле на экране, а не число | `ИтогТоваров = 600` |
| ПутьКДанным `Объект.ИтогТоваров` | Такого пути нет | ПутьКДанным `ИтогТоваров` |
| Реквизит создан внутри `Объект` | При добавлении была выделена строка в `Объект` | Удалить, выделить верхний уровень, добавить заново |
| `ТолькоПросмотр` у всей таблицы | Заблокируется ввод товаров | `ТолькоПросмотр` только у поля итога |

Одинаковые имена реквизита и элемента (`ИтогТоваров` и `ИтогТоваров`) не делают их одним объектом — это по-прежнему «температура и термометр». Подробнее — [разбор 1С о реквизитах и элементах формы](https://kb.1ci.com/1C_Enterprise_Platform/FAQ/Development/Controls/Attributes_and_items_of_the_form__referring_to_them_from_the_module_of_the_form/?language=en).

## Проверка

`Ctrl+S` → `F7` → открываем накладную в Предприятии:
- поле «Итого товаров» видно под таблицей товаров;
- ввести в него ничего нельзя;
- значение пока **0** — это нормально: кода, который его считает, ещё нет.

> [!question]- Проверь себя
> 1. Записался ли `ИтогТоваров` в документ после «Записать»?
> 2. Чем `ИтогТоваров = 0` отличается от `Элементы.ИтогТоваров.Видимость = Ложь`?
> 3. Почему путь к реквизиту формы не начинается с `Объект.`?
>
> > [!success]- Ответы
> > 1. Нет, это реквизит формы, а не документа.
> > 2. Первое меняет данные, второе — свойство элемента интерфейса.
> > 3. Реквизит лежит на верхнем уровне формы, а не внутри `Объект`.
