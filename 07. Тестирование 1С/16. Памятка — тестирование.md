> [!abstract] Коротко
> Памятка раздела для повторения и подготовки к собеседованию: главные термины, виды тестирования, техники тест-дизайна, что проверять в 1С, шаблоны тестов на встроенном языке, YAxUnit и Gherkin для Vanessa Automation, частые ошибки.

## Главные термины

| Термин | Коротко |
| --- | --- |
| Тест-кейс | Предусловия → шаги → ожидаемый результат |
| Ожидаемый / фактический результат | Что должно быть / что получилось |
| Дефект (баг) | Несоответствие фактического результата ожидаемому |
| Позитивный / негативный тест | Правильные данные / неправильные данные и действия |
| Регрессия | Сломалось то, что раньше работало |
| Ретест | Проверка, что конкретный дефект исправлен |
| Дымовой тест (smoke) | Быстрая проверка «вообще работает?» |
| Чёрный / белый ящик | Без знания кода / с учётом кода |
| Серьёзность / приоритет | Насколько вредит / насколько срочно |

## Уровни и пирамида

| Уровень | Пример в 1С | Инструмент |
| --- | --- | --- |
| Модульный | Функция расчёта суммы | Своя тестовая обработка, YAxUnit |
| Интеграционный | Движения при проведении | Тест в транзакции с откатом, YAxUnit |
| Системный / UI | Сценарий в форме | Vanessa Automation |
| Приёмочный | Проверка заказчиком | Сценарии Gherkin, ручная приёмка |

Много модульных — меньше интеграционных — мало UI.

## Техники тест-дизайна

| Техника | Когда | Пример |
| --- | --- | --- |
| Классы эквивалентности | Диапазоны значений | ≤ 0 / 1–99 / 100–1000 / > 1000 |
| Граничные значения | Любые границы | 0, 1; 99, 100; 1000, 1001 |
| Таблица решений | Несколько условий | Покупатель × строки × права |
| Переходы состояний | Документы | Записан → проведён → отмена → пометка |
| Предугадывание ошибок | Всегда | Пусто, ноль, конец месяца, двойное нажатие, роль |

## Что проверять в 1С

- Форма: пересчёт, сообщения, доступность.
- Запись **без формы** — обработкой, кодом.
- Проведение, **повторное** проведение, **отмена** проведения — движения регистров.
- Отчёты — итоги на известных данных, граница последнего дня.
- **Права** — под рабочей ролью, не под администратором.
- Одновременная работа, печать, обновление конфигурации.

## Шаблон модульного теста (своя обработка)

```1C
&НаКлиенте
Процедура Тест_ЧтоПроверяем_ПриУсловии() Экспорт
	// Подготовка
	Количество = 100;
	// Действие
	Результат = РасчетыКлиентСервер.СуммаСоСкидкой(Количество, 10);
	// Проверка
	ПроверитьРавенство(Результат, 950, "100 шт. — скидка 5%");
КонецПроцедуры
```

Интеграционный тест: `НачатьТранзакцию()` → создать и провести документ → проверить движения запросом → `ОтменитьТранзакцию()`.

## YAxUnit

```1C
Процедура ИсполняемыеСценарии() Экспорт
	ЮТТесты
		.ДобавитьТест("Скидка")
			.СПараметрами(99, 990)
			.СПараметрами(100, 950);
КонецПроцедуры

Процедура Скидка(Количество, Ожидаемое) Экспорт
	ЮТест.ОжидаетЧто(РасчетыКлиентСервер.СуммаСоСкидкой(Количество, 10)).Равно(Ожидаемое);
КонецПроцедуры
```

Запуск без участия человека: `/C RunUnitTests=путь\config.json`.

## Gherkin и Vanessa Automation

```gherkin
#language: ru
@smoke
Функционал: Название возможности

Контекст:
	Дано Я открыл новый сеанс TestClient или подключил уже существующий
	И я закрыл все окна клиентского приложения

Сценарий: Одно поведение
	Когда … действие …
	Тогда … проверка …

Структура сценария: Одно поведение на разных данных
	Когда … <Параметр> …
	Тогда … <Результат> …
	Примеры:
		| Параметр | Результат |
		| …        | …         |
```

| Помнить | |
| --- | --- |
| Менеджер тестирования | `/TESTMANAGER`, в нём открыта VA |
| Клиент тестирования | `/TESTCLIENT`, управляемое приложение |
| Нужно два сеанса | На учебной платформе выполнение, скорее всего, недоступно |
| Элементы — по имени | `ТоварыКоличество`, `ФормаЗаписать` |
| Каждое действие — с проверкой | «Тогда открылось окно…», «таблица стала равной…» |
| Запуск из командной строки | `/TESTMANAGER /Execute "…\vanessa-automation.epf" /C"StartFeaturePlayer;VAParams=…\VAParams.json"` |
| Только тестовая база | Никогда — рабочая |

## Частые ошибки

| Ошибка | Как правильно |
| --- | --- |
| Проверять только позитивные сценарии | На каждый позитивный — один-два негативных |
| Ожидаемый результат «всё работает» | Конкретное значение: «сумма 300» |
| Проверять под администратором | Тестовый пользователь с рабочей ролью |
| Проверять только форму | Ещё движения регистров и запись без формы |
| Сценарий без проверок | После каждого важного действия — «Тогда …» |
| Сценарии зависят друг от друга | Чистый старт, свои данные, эталонная база |
| Фиксированные паузы в сценарии | Шаги ожидания окна или значения |
| Автотесты на рабочей базе | Только на тестовой копии |
| Упавший тест «починили» удалением проверки | Найти причину: ошибка в программе или в тесте |

## Вопросы, которые задают на собеседовании

> [!question]- Проверь себя
> 1. Чем отличаются модульное, интеграционное и системное тестирование? Пример для 1С.
> 2. Что такое регрессионное тестирование и почему его автоматизируют?
> 3. Какие значения проверите для поля «скидка от 1000 ₽ включительно»?
> 4. Что должно быть в баг-репорте?
> 5. Как проверить проведение документа автотестом, не оставив мусора в базе?
> 6. Что такое BDD и Gherkin? Назовите ключевые слова.
> 7. Как устроен запуск сценариев в Vanessa Automation?
> 8. Почему тест может «мигать» и что с этим делать?
>
> > [!success]- Ответы
> > 1. Модульное — одна функция (расчёт суммы); интеграционное — части вместе (движения при проведении); системное — вся программа через интерфейс (сценарий в форме).
> > 2. Повторная проверка работавшей функциональности после изменений; автоматизируют, потому что набор растёт и вручную его не прогоняют регулярно.
> > 3. 999.99 (без скидки), 1000 (со скидкой), 1000.01; плюс классы: 0, отрицательная сумма, большая сумма.
> > 4. Заголовок, шаги воспроизведения с данными, ожидаемый и фактический результат, окружение, серьёзность, вложения и точный текст ошибки.
> > 5. На сервере в транзакции: создать и провести, проверить движения запросом по регистратору, отменить транзакцию.
> > 6. Подход «требования как исполняемые примеры поведения»; Gherkin — язык их записи: Функционал, Контекст, Сценарий, Дано, Когда, Тогда, И, Но, Структура сценария, Примеры.
> > 7. VA открывается в сеансе менеджера тестирования и управляет сеансом клиента тестирования тестовой базы, выполняя шаги из `.feature`-файлов; без участия человека — через командную строку и VAParams.json.
> > 8. Из-за зависимости от данных, порядка запуска, текущей даты или времени ожидания. Чистый старт, известные или собственные данные, явные даты, шаги ожидания вместо пауз.
